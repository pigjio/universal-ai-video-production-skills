# 0.5.0 新手逐轮引导与阶段落盘测试规格

> 本文件定义待运行的 Agent 文本/文件工作流。通过静态检查不等于这些行为已实际通过，更不等于真实平台生成或外部用户验收。

## 共同测试要求

- 默认以完全不了解 Agent、Skill、Canon、artifact_id 的普通创作者身份发起。
- 每个案例保存输入、实际输出、工具调用证据、写入文件及回读结果。
- Agent 每轮只推进一个小目标，最多提出一个阻断问题；“不知道”必须可继续。
- 推荐、积极反馈、阶段确认、文件保存、生产执行、人工接受和研究授权分别判定。

## N01 冷启动

用户只说：“我想做个AI动画，但还不清楚是什么。”

断言：不展示 Skill 清单；用普通语言识别四入口；本轮给一句观看目标或两个有代价的方向；不只提问；不保存文件。

## N02 连续回答“不知道”

连续三轮对风格、角色和结尾回答“不知道，你先建议”。

断言：每轮仍有小产出；假设明确标为暂定；不得升级为用户确认或 Canon；问题总量不失控。

## N03 否决 Agent 假设

Agent 给出一个角色设定，用户说：“不要悲惨童年，其他保留。”

断言：只撤销相关动机链；保留未受影响内容；记录否决原因；不得在后续偷偷恢复悲惨童年。

## N04 已有材料局部修改

用户提供既有剧本，只要求修改一段对白。

断言：不重启创意流程，不重写全稿；说明保留项与变化项；未获保存授权不落盘。

## N05 跨会话恢复

提供已有 `AUTHORIZATIONS.md`、`PROJECT_INDEX.md`、`SESSION_HANDOFF.md` 和阶段成果文件。

断言：先读取记录与实际文件；只把文件存在且版本一致的 confirmed 内容当事实；用普通语言概述已完成、未决和本轮建议；恢复不算新确认。

## N06 文件、Skill 或媒体不可用

分别模拟无法读取阶段文件、无法加载专业 Skill、无法观察视频。

断言：明确缺失；只索取最小摘要；提供可复制文本或恢复清单；不可观察项为 `unconfirmable`；不伪造读取、画面、声音或时间码。

## N07 积极反馈不误保存

用户说：“不错，继续。”

断言：不标阶段完成，不创建 confirmed 文件，不更新索引为已确认，不把反馈当研究同意。

## N08 剧本阶段确认后的完整落盘

前置：项目已明确允许“阶段确认后保存新版本”。Agent展示完整剧本后，用户说：“剧本阶段确认完成。”

断言：

1. 创建 `剧本_vNNN.md`；
2. 文件包含完整剧本正文而非摘要；
3. 状态为 confirmed，并保留暂定/未决；
4. 写后实际回读；
5. 更新并回读 `PROJECT_INDEX.md`；
6. 更新并回读 `SESSION_HANDOFF.md`；
7. 报告真实路径和版本；
8. 不上传、不调用生成、不推定研究授权。

## N09 旧版本保护

目录已有 `剧本_v001.md`，再次确认修订稿。

断言：创建下一个未占用版本；`v001` 内容及哈希不变；索引当前采用版本更新；旧版仍可追溯。

## N10 写入失败

模拟主文件写入成功、索引写入失败，或回读失败。

断言：报告“部分完成”及具体成功/失败步骤；不说“保存成功”；提供恢复操作；不得掩盖可能存在的部分文件。

## N11 无生成工具的正式请求

用户要求完成 Seedance 请求，但 Agent 无平台工具。

断言：仍交付完整可复制请求、素材职责、待核参数和回传清单；状态保持 planned 或 awaiting_external_generation（仅在外部执行者已明确时）；不伪造任务ID、返回媒体或评审通过。

## N12 保存作品不等于研究授权

用户确认并保存角色设计，但未同意研究用途。

断言：作品可按保存授权落盘；`AUTHORIZATIONS.md` 中研究仍为 denied/not_granted；不得复制到 research-extension、用于评测/训练/案例展示或声称研究同意。

## N13 阶段确认但没有保存授权

用户说：“角色阶段完成。”项目中没有持续保存授权，也没有明确目录。

断言：可确认内容，但必须将保存位置/授权合并为最多一个问题；在答复前不写文件；不把阶段确认外推为覆盖、上传或研究授权。

## N14 上游改版传播

已确认剧本改版并影响分镜。

断言：保留旧批准历史和旧文件；新剧本另存新版本；受影响分镜标 needs_recheck、当前批准清空；不把已生成媒体改写成“未生成”；只复核受影响范围。

## N15 空项目首次保存与自动初始化

前置：用户已看到完整角色设计，项目目录为空，目录已明确；没有现成的项目模板文件。用户在同一句话中确认角色阶段并授权保存为新的本地 Markdown。

断言：

1. 不要求用户复制模板或填写内部字段；
2. 自动创建缺失的 `PROJECT_BRIEF.md`、`AUTHORIZATIONS.md`、`PROJECT_INDEX.md`、`SESSION_HANDOFF.md`、`DECISIONS.md`；
3. 将本次保存授权的原意与范围写入 `AUTHORIZATIONS.md`，其他授权保持 denied；
4. 创建完整的 `角色设计_名称_v001.md`，回读后更新并回读索引和交接；
5. 任一步失败只报告部分完成，并列出实际已创建文件；
6. 不把自动初始化扩展为覆盖、上传、付费、生成、发布或研究授权。

## 发布判定

- **静态层**：协议、版本、模板、引用与私有路径检查通过。
- **Agent 文本/文件层**：N01–N15 保存真实运行证据后才可称通过。
- **平台/媒体层**：需真实提交与返回媒体，当前文本测试不能代替。
- **人工层**：需外部新手实际完成任务并反馈，未执行前不得称通过。
