# 生产模式、能力核验与真实基线

加载条件：每轮启动、无生成工具、提交/失败处理或基线比较时加载。公共状态与授权以 common-contract.md 为准。

## 1. 从目标进入，不从平台套餐进入

1. 冻结 creative_mode、subject_type、完成判据、上游 ID→版本和本轮授权。general 为默认；只有用户选择课堂练习才约束为单角色、单场景、单动作。
2. environment-led 核对空间锚点、材料与光色；object-led 核对结构、支撑和状态；abstract 核对范围、形态、路径和终点。三者 character:null 合法，不补人物冲突。无运动任务返回静态提示词分支。
3. 区分文件可访问、内容已观察、实际已上传。上传日志缺失不能填“绑定成功”；纯文字任务可无图，但不能宣称继承图像身份。
4. 核验能力后才分请求：模式、模型版本、窗口/分辨率、参考槽位、首尾帧、续接、多镜头、种子、音频、额度和输出获取方式。每项记录来源、核验日期、适用模式及 known/unknown；文档声称支持与本项目实测稳定分栏。
5. 选择长短与接口见 clip-continuity.md。未知能力不填固定秒数，不猜 API 参数；交待核验项与可复制合同。

## 2. 提交与状态核验

| 条件 | 动作和记录 | 失败回退 |
|---|---|---|
| 仅授权写稿 | 交完整文本、素材职责、计划参数；不调用 | 等待上传/费用授权，不把写稿批准解释成提交批准 |
| 无工具、需外部执行 | clip 为 awaiting_external_generation；附回传清单 | 无回传时保持等待，不制造基线 |
| 必需素材缺失 | planned + blocked_reason，列资产 ID、版本和职责 | 请求素材；改纯文字须另获授权并另存候选 |
| 具备工具、权限和输入 | 保存提交前快照及真实上传回执，调用一次 | 错误先查受理情况，避免重复扣费 |
| 有任务 ID 无输出 | submitted，保存查询记录 | 超时继续查任务或移交人工，不填 generated |
| 无任务 ID 且受理不明 | planned + submission_uncertain | 查服务记录/账单；不盲重试 |
| 明确失败 | failed，保留错误和已知任务 ID | 判断输入/能力/额度原因，授权后新请求重试 |
| 实际可访问输出 | generated，绑定输出 ID/文件；转 under_review | 损坏文件记录解码失败；先取回有效资源，不能判画面质量 |

依赖真实尾帧的后续请求必须等接口观察合格；独立请求才可在授权范围内并行。回传至少包括实际提交文本、模型/参数、上传资源及职责、任务/输出 ID、可访问原片、错误日志和用户修改说明。无某项就标未知，不从计划补造实际。

## 3. 基线账本与比较纪律

- `first_return_baseline`：本轮第一份真实返回，失败也保留；`accepted_baseline`：另有评审/批准证据的受保护版本。两者不必相同。无结果时两者均 null。
- 每个候选保留请求 ID、输入版本快照、参数、输出路径、观察范围、症状证据、成本信息（若可得）、人工决定和回退路径。
- 比较前冻结完成判据及保护项，再列 allowed_changes。诊断默认只动一个主变量，平台/模型/素材/镜头内容尽量一致；不能一边改提示词一边换模型却归因给措辞。
- 种子可控则记种子及仍可能存在的服务非确定性；不可控则记随机性混杂。预算允许时重复各候选、交替顺序并保留所有失败，不挑最佳一次作普遍结论。报告逐次结果和覆盖范围，不凭小样本宣布稳定率。
- 修复相互矛盾的图像状态与文字时可联合更换；记录必要耦合和无法分离贡献的限制。它是修复包比较，不是单变量因果试验。
- 晋级须重新观察目标缺陷、原通过项及前后接口。人工 pending 可交评审，不可覆盖人工批准基线；候选变差则恢复受保护版本，保留失败证据。

## 4. 完成小例（教学推演，不是实际生成记录）

任务：environment-led / perceptual，无角色，固定机位观察废墟中雾从左侧孔洞进入，在地面右半区停留；废墟就是基准，不先恢复完整建筑。已授权写稿，但本环境无生成工具。

执行产出：character:null；空间锚点为左侧孔洞、中央断柱、右侧地面；主体白名单为建筑和雾；请求窗口 unknown，平台能力待外部核验。完整提交文本描述固定机位、废墟几何不变、雾的入口/路线/终止范围、不新增人物与孔洞；实际上传为空。clip 的 production_status=awaiting_external_generation，returned_task_id/result_file/baseline 均 null，human_decision=pending。

外部操作清单：先核验目标模式及窗口→上传实际需要的参考并记录回执→保存完整实际提交→授权生成→回传原片与任务记录→按雾路线和空间锚点评审。若只回截图，只建立该帧证据，不能称运动通过。若回传失败日志，记 failed，不把计划效果写成失败画面的观测。若长段出现断柱漂移，先定位区间及排除后期镜像，再试局部分组，不直接重做废墟母版。
