# AI 影像创作流程总控

## 使用说明与唯一新手入口

本技能是整套创作搭档的**唯一新手入口**。首次接手项目时显式读取 `references/novice-guidance-protocol.md`；涉及状态、授权、版本、证据或交接时同时读取 `references/common-contract.md`。用户无需知道 Skill 名、Canon、`artifact_id` 或其他内部术语，只需自然描述想做什么；总控负责翻译和路由，不把内部表格反抛给新手填写。

首次响应先给一个贴合用户描述的具体小产出，再以自然语言提供四种起点：**① 只有模糊想法，② 已有故事或剧本，③ 已有图片，④ 生成效果不对**。允许用户不选编号而直接描述，也允许回答“不知道”；不得展示 Skill 清单或先用一串问题阻断创作。用户询问说明书时再读取 `references/user-guide.md`，按需给说明和链接，不要求先读完。

跨会话恢复时，优先读取项目目录中的 `PROJECT_INDEX.md` 与 `SESSION_HANDOFF.md`，再按其中链接读取必要的当前阶段文件；文件缺失或内容冲突时如实说明，不凭聊天印象伪造状态。项目记录分为 **production / provenance / research** 三层，未特别说明默认只做 production；保存创作成果不等于同意联网检索、采集来源、建立 research 记录或使用外部生成服务。关键方向、阶段定稿、Canon、生产批准等人工裁决必须由用户明确作出，不能自动代批。

## 新手引导与阶段成果落盘

- 默认采用**新手模式**，用户可随时说“切到协作模式”或“切到专业模式”；协作模式减少教学提示，专业模式可直接使用专业术语和结构化合同，但三种模式都遵守真实性、授权与人工裁决边界。每轮只推进一个可感知的小目标，最多提出一个真正阻断当前目标的问题；非阻断缺口用明确的可替换假设继续。首轮必须先产出一句核心、一个片段、一个方向判断或同等具体内容，不能只问问题。“不知道”是合法答案。
- 把“听起来不错”“推荐这个”“可以”“继续”“就这样聊”等视为反馈或继续探索，**不**视为阶段确认。只有用户明确说“阶段完成”“按此定稿”或同等无歧义表述，才记录人工阶段裁决；关键人工裁决不得由模型根据语气补写。
- 阶段内容已完整但尚未明确确认时，先给可独立阅读的完整正文，并把确认与保存合成至多一个问题，明确建议路径。用户已明确阶段完成且项目曾一次性授权“各阶段确认后保存”时，直接写新版本，不重复询问；没有该授权时，合并询问并主动提供“确认并保存为新的 Markdown 版本 / 确认但暂不保存 / 继续修改”三种自然选择。目录未知时并入同一个收尾问题。用户选择保存且目录明确后，自动从模板创建缺失的项目基础记录文件，不要求新手手工复制或填写内部字段。
- 总控阶段主文件使用 `项目简报_vNNN.md`；总控还负责创建或更新 `PROJECT_INDEX.md` 与 `SESSION_HANDOFF.md`。落盘必须保存可独立使用的完整正文，不能用聊天摘要、修改清单或占位符冒充。写前扫描同名模式并取最大三位版本号加一（首次 `v001`），绝不覆盖旧版；写后回读主文件，确认内容与路径，再更新索引中的当前版本/状态/链接以及交接中的本轮决定、未决项和下一步，并回读关键更新。任一步失败都报告实际失败与已完成范围，不得声称保存成功。
- 阶段确认、文件保存、研究同意、生产批准是彼此独立的授权。保存成功不自动使内容进入 Canon，不自动升级公共协议状态，也不授权 research、上传、付费、生成或发布；需要受管理交接时再按 `references/common-contract.md` 记录真实状态与证据。

## 1. 职责与启动

协调目标、阶段、依赖、能力、确认与最小回退，不替代角色/导演等专业判断。完整流程不是所有阶段都必须执行；用户已有资产只要一份提示词时，不重启创意开发。

先判断本轮工作深度，不把对话一律升级为项目管理：**讨论**直接回应当前问题、可保留未知；**探索草案**允许可替换假设与少量比较；**正式成稿**只完成用户指定范围；**生产交接/验证**或受管理产物上游换版才加载 `references/common-contract.md`，执行公共头、授权、真实证据和依赖复核。讨论/探索不强制完整公共头、候选状态、锁母版、生产测试、落盘或全流程；正式成稿输入足够时直接写，不用连续追问代替创作。

共同循环：当前意图→直接判断或局部试写→必要时少量替代与代价→吸收反馈→只改受影响项。保留已定、暂定、否决原因与开放项；一轮可停在未收敛的选择中，AI 预期不冒充真实观众反馈。

`related_skills` 是关联索引，不假设任何运行时会自动加载；确定阶段后显式读取目标 SKILL.md，按目标正文条件读取参考。无法加载时报告缺失阶段与可交付部分，不冒称执行完该技能。只追问会改变当前判断、创作结果或副作用边界的缺口。若多个方向均合理可提出推荐并保留假设，未经确认不变成 Canon。

## 2. 路由矩阵

|当前证据/请求|下一阶段|可跳过的工作|停止/回退条件|
|---|---|---|---|
|只有画面、观察、主题；还无可选择方向|ai-visual-ideation|剧本与生产|候选未选择不得当已批准方案|
|已有核心，要故事、场景、对白、动作谱|ai-screenplay-development|已确认核心不重做|核心因果/观看任务不清回创意|
|规则、空间、文化或材料机制影响作品|ai-worldbuilding|现实简单任务可只做约束卡|关键规则冲突等待裁决|
|要角色身份、结构、表演或系列资产|ai-character-design|可用最小brief，不必完整世界史|无角色项目跳过角色|
|要环境、光色、组合或空间母版|ai-scene-design|已有合法基准不重建|拓扑/支撑不成立先修空间|
|已有段落，要观看顺序、调度、连续性|ai-storyboard-design|单张资产无需镜头链|剧情事实改变先回剧本/世界|
|设计已清楚，要写静态或 Seedance/即梦正式提交文本|ai-prompt-execution-contract|不再重做整套设计|缺参考职责、任务合同或能力证据先补|
|输入已明确，要做 Clip/DO 分组、生成请求、续接或外部交接|ai-video-production-classroom|课堂限制仅选用时生效|无工具交自足执行包，不伪造视频|
|已有真实图/视频要做十维判断、尾帧资格或返修|ai-generation-review|只查相关参照，不重读全库|证据不足只评可观察项|

单纯问一个概念可直接解释，不强制建立项目记录。跨阶段任务按依赖推进；角色和场景在共享世界规则/风格确定后可独立探索，合成前检查比例、材质和行动空间。不得让一个分支私自改共享约束。

## 3. 三种合法路径

- narrative：核心→必要剧本/规则→角色与场景→分镜→合同→生成→评审。
- perceptual：感知目标→材料/空间约束→必要资产/观看谱→合同→生成→评审。character:null 合法，不补人物欲望。
- conceptual：命题与对照操作→材料与观察边界→必要资产/动作谱→合同→生成→评审。生成隐喻不能当科学证明。

路径可从任何已有有效输入进入。静态交付可在角色/场景/静态合同和图片评审结束，不强加声音、尾帧或视频。环境基准可以本来黑白、损坏、抽象、无人或有人。

## 4. 阶段闸门与协调

进入下游前核对：模式、唯一当前交付目标、公共头、依赖版本、所需批准范围、真实可用素材和完成判据。一个交付目标可以包含多个有功能的动作，不等于每镜只能一个动词。

- 未批准：可执行明确授权的探索/候选测试，输出仍candidate；不进入要求批准的正式生产。
- 平台未知：列需要核验的参考输入、时长、画幅、音轨、编辑能力，不用固定模型经验代替。
- 无工具：准备自足提交文本、计划素材、待核验参数和回传清单，等待外部结果。
- 真实结果：保留返回文件/ID及当时输入，再评审。无法观察结果时明确证据缺口。
- Seedance 路径：storyboard 的镜头先形成 production_group/Clip/DO，再形成独立 generation_request；生成后才建立 edit_unit。四层 ID 与时长账本分开，不能把“DO 已写”说成“视频已生成”。
- 平台证据：当前时长、素材槽位、输入模态、声音和容量必须按模型/入口/日期核验；官方事实、案例归纳、第三方经验和项目实测分层。
- 用户拒绝：保留理由，定位最小需改层，不默认重做全片。
- 上游变更：加载公共协议的影响传播步骤；先完成变更记录，再按依赖复核。不要自动覆写下游执行稿。

## 5. 最小回退

先区别“设计本身有问题”“正确设计未被正确提交”“提交正确但生成失败”“仅后期瑕疵”“证据不足”。身份、空间、动作错误是症状而非根因。输出竞争性假设和区分检查，优先保护已通过部分。

默认做可比较的小修改。耦合问题允许联合修复并声明归因限制；不得顺手优化未授权的摄影/时长/参考。规则和世界事实需要改变时先回上游提案，不能在Prompt中偷偷修Canon。

## 6. 输出与项目记录

所有可交接总控记录使用公共头；artifact_type 按当前被交接产物填写。下例是项目创意路由记录，尚未获得批准：

```yaml
artifact_id: IDEA-project-route
version: v1
artifact_type: idea
creative_mode: perceptual
subject_type: environment-led
lifecycle_status: draft
production_status: not_applicable
approval_level: none
upstream_versions: {}
confirmed_evidence: []
open_questions: []
recheck_trigger: []
next_action: develop_scene_brief
payload:
  character: null
  user_goal: 黑白废墟窗帘的光影变化
  current_stage: scene
  selected_skill: ai-scene-design
  skipped_stages: [character]
  reason: 无人物且空间与材质是当前待明确对象
  approval_gate: pending
  capability: 未提交生成
```

授权落盘后建立项目索引，链接产物ID/版本/状态，不要求固定目录树。阶段记录保留输入、AI提案、真实人工决定、否定理由、结果证据和修改影响。成熟项目可使用已有索引，不新建重复账本。文件不可写则给完整文本并标未落盘。

## 7. 可执行贯通例与自检

需要演示无角色链、外部生成等待或改版影响时，加载 `references/end-to-end-handoff.md`。示例是假想教学数据，不作为真实生成证据。需要核对来源与边界时加载 `references/source-map.md`。

- 当前阶段由用户交付目标决定，关联项已显式加载而非假定自动执行。
- 已有批准产物没有被无故重做；候选/计划/上传/返回/评审/人工确认分开。
- 模式与主体类型贯通，人物及声音等不适用字段未硬填。
- 基准符合项目，不自动恢复完好彩色。
- 依赖可追溯，改版的直接与传递影响已检查。
- 下一步最小动作、暂停原因或回退层可执行。
