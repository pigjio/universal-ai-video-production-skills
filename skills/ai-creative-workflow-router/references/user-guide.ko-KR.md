# 범용 AI 영상 제작 Skills 사용 설명서

[중국어 안내](user-guide.md)｜[한국어 안내](user-guide.ko-KR.md)

적용 버전: **0.6.0｜시나리오·스토리보드·Seedance 창작 협업 강화 버전**.

## 1. 처음 사용할 때

Skill 이름을 알거나 프롬프트 작성법을 먼저 배울 필요가 없습니다. 다음 중 현재 상황에 가까운 것을 Agent에게 말하거나, 가지고 있는 자료를 바로 설명하세요.

1. 막연한 아이디어만 있습니다.
2. 이미 이야기나 시나리오가 있습니다.
3. 이미지를 가지고 있습니다.
4. 생성 결과가 원하는 방향과 다릅니다.

다음 문장을 복사해서 시작해도 됩니다.

> Agent를 처음 사용합니다. 지금 제게는 【아이디어 / 이야기 또는 시나리오 / 이미지 / 만족스럽지 않은 생성 결과】가 있습니다. 한 번에 작은 목표 하나씩 진행해 주세요. 제가 모르겠다고 하면 쉽게 비교할 수 있는 선택지를 제안해 주세요.

Agent는 첫 응답부터 구체적인 작은 결과물 하나를 제시해야 하며, 긴 질문 목록만 보내서는 안 됩니다. “모르겠어요”, “먼저 제안해 주세요”, “어느 쪽이든 괜찮아요”도 모두 유효한 답입니다.

## 2. 세 가지 대화 방식

- **초보자 모드**: 기본값이며 쉬운 말로 한 단계씩 진행합니다.
- **협업 모드**: 사용자와 Agent가 함께 대안을 비교하고, 시험 작성하고, 수정합니다.
- **전문가 모드**: 전체 상태, 의존성, 제작 필드, 인계 내용을 표시합니다.

언제든 “더 쉽게 설명해 주세요”, “저와 함께 검토해 주세요”, “전문 제작 절차로 진행해 주세요”라고 말할 수 있습니다. 대화 방식을 바꾸는 것만으로 작품이 자동 확정되지는 않습니다.

## 3. 사용자가 할 일은 네 가지입니다

- **설명**: 현재 가진 아이디어나 자료를 Agent에게 알려 줍니다.
- **비교**: 어떤 안이 의도에 더 가까운지 말합니다.
- **거절**: 원하지 않는 요소와 그 이유를 분명히 말합니다.
- **확정**: 전체 단계 산출물을 확인한 뒤 계속 수정할지, 단계를 완료할지 결정합니다.

Agent는 내부적으로 적합한 Skill을 선택하고, 필요한 용어를 설명하고, 버전을 관리하고, 의존성을 검사하고, 파일을 저장합니다. 사용자가 Canon이나 `artifact_id` 같은 전문 필드를 직접 작성할 필요는 없습니다.

## 4. 처음부터 전체 과정을 밟을 필요는 없습니다

| 지금 가지고 있는 것 | 바로 할 수 있는 작업 |
|---|---|
| 막연한 아이디어 | 창작의 핵심과 방향 비교 |
| 기존 시나리오 | 부분 진단, 수정 또는 다음 단계 디자인 |
| 기존 캐릭터·장면 이미지 | 자산 보정, 스토리보드 또는 생성 계약 |
| 기존 스토리보드 | 제작 그룹, 정식 요청, 영상 제작 계획 |
| 기존 생성 결과 | 증거 기반 리뷰, 문제 진단, 부분 수정 |

기존 자료는 기본적으로 사용자가 요청한 범위에서만 수정합니다. Agent는 절차를 보여 주기 위해 이미 확정된 내용을 다시 만들어서는 안 됩니다.

## 5. 각 대화에서 진행하는 방식

Agent는 한 번에 명확한 작은 목표 하나만 진행하며, 실제로 진행을 막는 질문은 최대 하나만 합니다. 나머지 불확실한 내용은 “Agent의 임시 가정”으로 표시할 수 있고 사용자는 언제든 바꿀 수 있습니다.

“좋아요”, “괜찮아요”, “계속해 주세요”, “방향이 맞아요”는 긍정적인 피드백일 뿐, 다음 항목에 자동으로 동의한다는 뜻이 아닙니다.

- 단계 완료
- 파일 저장
- 제작 승인
- 업로드 또는 유료 생성
- 사람의 최종 승인
- 연구 사용 동의

## 6. 한 단계를 확정하는 방법

Agent가 해당 단계의 전체 산출물을 보여 준 뒤에는 **새 Markdown 버전으로 확정 후 저장 / 확정하되 지금은 저장하지 않기 / 계속 수정** 중 하나를 선택하도록 안내합니다. 사용자가 직접 다음처럼 말해도 됩니다.

> 이 단계를 완료된 것으로 확정합니다.

또는 다음처럼 말할 수 있습니다.

> 시나리오는 이 버전으로 확정하고 캐릭터 디자인으로 넘어가 주세요.

이와 같이 명확하게 표현해야만 단계가 `confirmed` 상태가 됩니다. “확정하되 지금은 저장하지 않기”를 선택하면 파일을 쓰지 않습니다. “계속 수정”을 선택하면 draft/candidate 상태를 유지합니다. 아직 결정하지 않은 내용이 있다면 draft/candidate로 저장해 달라고 명시할 수도 있으며, 초안을 확정본처럼 취급해서는 안 됩니다.

## 7. 단계별로 저장되는 파일

| 단계 | 기본 파일 이름 |
|---|---|
| 프로젝트 시작 | `项目简报_vNNN.md` |
| 아이디어 | `创意核心_vNNN.md` |
| 시나리오 | `剧本_vNNN.md` |
| 세계관 | `世界观设定_vNNN.md` |
| 캐릭터 | `角色设计_名称_vNNN.md` |
| 장면 | `场景设计_名称_vNNN.md` |
| 스토리보드 | `分镜_场次_vNNN.md` |
| 생성 계약 | `生成请求_对象_vNNN.md` |
| 영상 제작 | `视频生产计划_vNNN.md` |
| 결과 리뷰 | `生成评审_对象_vNNN.md` |

파일에는 다른 대화 없이도 이해할 수 있는 완전한 산출물이 들어 있어야 합니다. 대화 요약이나 수정 목록만 저장해서는 안 됩니다. 수정할 때마다 새 버전을 만들며 기존 버전을 조용히 덮어쓰지 않습니다.

## 8. 최초 저장과 지속 저장 권한

처음 저장할 때는 Agent에게 프로젝트 폴더만 알려 주면 됩니다. 폴더가 명확하고 저장 권한이 유효하면 Agent가 누락된 `PROJECT_BRIEF.md`, `AUTHORIZATIONS.md`, `PROJECT_INDEX.md`, `SESSION_HANDOFF.md`, `DECISIONS.md`를 자동으로 만들고 현재 확인된 최소 정보를 기록합니다. 사용자가 템플릿을 복사하거나 전문 필드를 직접 채울 필요는 없습니다. 기존 파일을 빈 템플릿으로 덮어쓰지 않습니다.

### 단계 저장 권한을 한 번에 설정하기

프로젝트를 시작할 때 다음처럼 말할 수 있습니다.

> 이 프로젝트에서는 앞으로 제가 각 단계의 완료를 명확히 확정한 뒤, 기존 버전을 덮어쓰지 않고 새로운 로컬 Markdown 전체 버전을 자동으로 저장하고 프로젝트 인덱스와 세션 인계 문서를 업데이트하는 것에 동의합니다. 이 동의에는 초안 저장, 덮어쓰기, 삭제, 업로드, 유료 생성, 게시 또는 연구 사용이 포함되지 않습니다.

이 권한은 단계마다 “저장할까요?”라고 반복해서 묻는 과정을 줄이기 위한 것입니다. 각 단계의 내용 완료는 여전히 사용자가 명확하게 확정해야 합니다.

완전한 저장 작업에는 다음 네 단계가 모두 포함됩니다.

1. 새로운 단계 주 파일 생성
2. 주 파일을 다시 읽어 내용 확인
3. `PROJECT_INDEX.md` 업데이트 후 재확인
4. `SESSION_HANDOFF.md` 업데이트 후 재확인

어느 한 단계라도 실패하면 Agent는 “완료되지 않음” 또는 “일부 완료”라고 말하고 실패한 위치를 알려야 합니다. 저장이 성공했다고 잘못 말해서는 안 됩니다.

## 9. 다음 세션에서 이어가는 방법

새 대화에서 다음처럼 요청하세요.

> `AUTHORIZATIONS.md`, `PROJECT_INDEX.md`, `SESSION_HANDOFF.md`를 먼저 읽고 현재 단계에서 채택한 전체 파일도 읽어 주세요. 어디까지 확정되었는지 쉬운 말로 알려 준 뒤, 한 번에 작은 목표 하나씩 진행해 주세요.

Agent는 인덱스, 인계 문서, 실제 파일이 서로 일치하는 `confirmed` 내용만 사실로 취급해야 합니다. 파일이 없거나 버전이 충돌하면 재검토가 필요하다고 표시해야 하며, 대화 기억만으로 확정본을 만들어서는 안 됩니다.

## 10. 스토리보드에서 Seedance / Jimeng 제작으로 넘어가기

작품 완성이 목표라면 Agent에게 다음 세 가지 결과를 순서대로 만들어 달라고 요청할 수 있습니다.

```text
만족할 때까지 논의한 시나리오
→ 각 숏에 시나리오 근거가 있는 스토리보드
→ 숏별로 바로 복사할 수 있는 Seedance / Jimeng 영상 프롬프트
```

내부에서 사용하는 장르 이론, 구조 이론, 숏 크기 분류를 먼저 공부할 필요는 없습니다. “너무 평범해요”, “영화적인 느낌이 부족해요”, “인물이 제가 원한 사람 같지 않아요”, “이 부분이 느려요”, “숏이 너무 잘게 나뉘었어요”, “세 번째 숏만 바꿔 주세요”라고 바로 말해도 됩니다. Agent는 차이가 분명한 소수의 안을 제시하고 영향받지 않은 내용을 보호해야 합니다.

정식 제작 순서는 다음과 같습니다.

```text
스토리보드 숏
→ production_group / Clip / DO
→ generation_request(플랫폼 요청 1회)
→ 실제 반환 결과
→ 10차원 리뷰
→ edit_unit(편집에서 실제 사용하는 구간)
→ 사람의 최종 판단
```

Agent는 복잡한 동작을 여러 번의 생성으로 나눌 필요가 있는지 먼저 판단하고, 프롬프트를 작성하기 전에 그 이유를 쉬운 말로 설명해야 합니다. DO 또는 프롬프트가 완성되었다는 것은 계획이나 요청 초안이 준비되었다는 뜻일 뿐, 업로드·생성·통과가 완료되었다는 뜻은 아닙니다.

## 11. 플랫폼 기능과 증거

영상 길이, 소재 수, 사운드, 시작·종료 프레임, 편집 기능은 모델과 제품 진입점에 따라 바뀔 수 있습니다. Agent는 출처, 확인 날짜, 모델, 진입점, 생성 모드를 기록해야 하며 과거 경험을 영구적인 규칙처럼 표현해서는 안 됩니다.

이미지만으로 움직임이나 소리를 입증할 수 없습니다. 영상을 관찰할 수 없는 경우 Agent는 평가 가능한 항목과 평가할 수 없는 항목을 구분해야 하며, 타임코드나 통과 결과를 꾸며 내서는 안 됩니다. 정체성 드리프트는 원인을 조사해야 하는 증상이며 캐릭터 디자인 문제로 자동 단정해서는 안 됩니다.

## 12. 저장은 연구 사용 동의가 아닙니다

로컬 저장은 업로드, 생성, 결제, 게시, 평가, 학습, 연구, 공개 전시, 2차 사용과 완전히 별개의 행동입니다. 연구 사용은 기본적으로 비활성화되어 있으며, 목적·범위·보관 기간·공유 대상·철회 방법을 별도로 설명하고 명확한 동의를 받아야 합니다.

## 13. 파일이나 도구를 사용할 수 없을 때

- **파일을 읽을 수 없음**: Agent는 읽을 수 없는 항목을 밝히고, 현재 목표를 계속하는 데 필요한 최소한의 요약만 요청해야 합니다.
- **Skill을 불러올 수 없음**: Agent는 누락된 전문 단계와 여전히 수행할 수 있는 부분을 설명해야 합니다.
- **생성 도구가 없음**: 복사해 사용할 수 있는 완전한 요청문, 소재 역할, 결과 회수 목록은 제공할 수 있지만 작업 ID나 결과를 꾸며 내서는 안 됩니다.
- **미디어를 관찰할 수 없음**: 판단할 수 없는 항목을 `unconfirmable`로 표시하며 실제로 보거나 들은 것처럼 말해서는 안 됩니다.
