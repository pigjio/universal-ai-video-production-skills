# 创作意图跨阶段追踪与局部修改

在剧本转分镜、分镜转请求、跨阶段局部修改或“为什么这样拍”时加载。复用已有版本、镜头与请求编号，不新建数据库、第二套状态机或学生作业表。只跟踪一旦丢失就会改变作品意思的事实。

## 1. 跟踪哪些内容

- 决定及其触发：角色因为什么选择，主动还是被迫。
- 首次信息揭示：角色和观众分别何时知道，禁止提前露出什么。
- 关键物件：谁持有、位置、接触、损坏/修复等状态。
- 动作与声音接力：前镜结束到后镜开始，未完成相位/持续声轨。
- 用户保护范围：不可改的台词、结局、镜头、基准或已接受资产。

环境/抽象项目改跟踪感知目标、材料变化、观看次序与终点，不补角色动机。普通单张提示词不用创建剧本编号。

## 2. 最小映射

在已有产物 payload 或阶段正文中放一个小节即可：

```text
依据：SCRIPT-01 v2 / SC02-B03（没有编号时用场次+精确原句）
意图：她看见扣袖口失败，主动决定留下。
覆盖：SH05 看见困难 → SH06 放下行李 → SH07 靠近帮助
请求：REQ03 覆盖 SH05/SH06；REQ04 覆盖 SH07
保护：观察早于决定；行李留门边；帮助由她发起。
验证：当前仅文本覆盖；视频尚未生成，不能标已验收。
```

ID 属于当前项目时才使用，不把示例 ID 当真实上游。映射可一对多、多对一；不可用“每句剧本=一镜=一次请求”。每个重要意图应有可读覆盖，每个新镜头应能解释作用；不追踪每个无关形容词。

## 3. 修改传播步骤

1. 引用旧版本与用户本次允许变化，明确保护范围。
2. 写出实际差量：动机、信息时点、空间、道具、声音、时长或只改措辞。
3. 查直接消费者，再沿镜头→请求→真实素材→剪辑采用与评审查传递影响；同一请求中共用素材/连续状态也需检查。
4. 分类为“要改”“只需复核”“可保留并说明理由”“未知待查”。依赖清单不完整时不能断言其他全部无影响。
5. 只有在授权范围内才写新版本；需改保护范围时给最小替代并等待裁决。旧批准与生成事实保留，受影响当前批准失效按公共协议处理为 needs_recheck。
6. 回归检查触发先后、首次揭示、物件状态、动作/声音接力、保护项与请求自包含。逐项对照前镜末态与后镜首态：动作若被提前到前镜完成，后镜要明确“保持已获得的视线/接触/持物状态”，不能再次发起同一动作或播放同句台词。若只允许改当前镜，优先保留原接口；必须改相邻镜时先说明并提案，不宣称相邻镜完全无影响。文字更新不等于视频已更新或合格。

新手只看到“改了哪里、为什么、哪些不动、还有哪项待决定”。后台检查不是要求每次回复展示全套表格；用户追问时再展开依据。

## 4. 两种容易错的局部修改

**删除看到困难的镜头**：若 SH05 被删，SH06 的留下可能失去原因。可以将困难与视线移入 SH06 的同一镜，而不是无条件保留结果；这会改变构图/时长，应先提案。确认后只更新受影响镜头和请求，SH07 是否受影响取决于其起始状态、共享请求与参考。

**只改交接物件的一只手**：交接镜的伸手、接触、释放要改；下一镜若看得见持物手也需复核；远处空景可保留。用户要求“只改第三镜”且第四镜依赖旧手时，说明冲突，不能偷偷改第四镜或假装完全不影响。可建议第三镜结束前恢复原持有状态，但那也是需要确认的动作变化。

## 5. 失败信号与来源

失败信号：反应先于触发；新旁白提前泄密；物件重复出现；已完成动作在新请求重演；只更新文字仍沿用旧片的当前批准；所有镜头一律重做；要求学生手填依赖。

本方法是公共协议已有 upstream_versions、传递复核和生产四层 ID 的轻量连接，不声称是某本书的原始理论。因果阅读依据 Glebas 蒸馏、镜头作用与连续性依据 Katz 蒸馏；映射字段、差量分类和例子是本包原创工程综合。
