# 通用 AI 影像制作 Skills 使用说明

[中文说明](user-guide.md)｜[한국어 안내](user-guide.ko-KR.md)

适用版本：**0.6.0｜剧本、分镜与 Seedance 创作协作增强版**。

## 1. 第一次使用

你不需要知道 Skill 名，也不需要先学提示词。直接告诉 Agent 你属于哪种情况，或直接描述材料：

1. 我只有一个模糊想法；
2. 我已有故事或剧本；
3. 我已有图片；
4. 生成效果不对。

推荐复制：

> 我是第一次使用 Agent。我现在有【想法 / 故事或剧本 / 图片 / 不理想的生成结果】。请一次只带我完成一个小目标；我不知道时给我容易比较的选项。

Agent 应在第一轮给出一项具体小产出，而不是只发长问卷。“不知道”“你先建议”“都可以”都是有效回答。

## 2. 三种交流方式

- **新手模式**：默认，用普通语言一步步推进。
- **协作模式**：你和 Agent 共同比较、试写和修改。
- **专业模式**：显示完整状态、依赖、生产字段和交接内容。

可以随时说“简单一点”“和我一起推敲”或“按专业流程”。切换方式不会自动确认作品。

## 3. 你只需要做四件事

- **描述**：告诉 Agent 你已有的想法或材料；
- **比较**：说出更接近你的方案；
- **否决**：明确不要什么以及原因；
- **确认**：在完整成果展示后，决定继续修改还是确认阶段完成。

Agent 负责内部选择 Skill、解释必要术语、维护版本、检查依赖和保存文件。你不用填写 Canon、artifact_id 等专业字段。

## 4. 不必从头走完整流程

| 你现在有什么 | 可以直接做什么 |
|---|---|
| 模糊想法 | 创意核心与方向比较 |
| 已有剧本 | 局部诊断、改写或下游设计 |
| 已有角色/场景图 | 资产校准、分镜或生成合同 |
| 已有分镜 | 生产组、正式请求和视频生产计划 |
| 已有生成结果 | 证据评审、故障诊断和局部返修 |

已有材料默认只改你提出的范围。Agent 不应为了展示流程而重做已确认内容。

## 5. 每轮如何推进

Agent 每轮只推进一个清楚的小目标，最多提出一个真正阻断的问题。其他未知可先作为“Agent 暂定假设”，你可以随时改掉。

“不错、可以、继续、方向对了”只表示积极反馈，不自动等于：

- 阶段完成；
- 文件保存；
- 生产批准；
- 上传或付费生成；
- 人工接受；
- 研究同意。

## 6. 如何确认一个阶段

当 Agent 展示该阶段完整成果后，它会主动用一个问题让你选择：**确认并保存为新的 Markdown 版本、确认但暂不保存、继续修改**。你也可以直接说：

> 我确认本阶段完成。

或者：

> 剧本按这版定稿，进入角色设计。

只有这类明确表达才能把阶段标为 `confirmed`。选择“确认但暂不保存”时不会写文件；选择“继续修改”时保持 draft/candidate。如果还有未决定内容，也可以明确要求保存为 draft/candidate；草稿不能冒充定稿。

## 7. 每个阶段保存什么

| 阶段 | 默认文件 |
|---|---|
| 项目启动 | `项目简报_vNNN.md` |
| 创意 | `创意核心_vNNN.md` |
| 剧本 | `剧本_vNNN.md` |
| 世界观 | `世界观设定_vNNN.md` |
| 角色 | `角色设计_名称_vNNN.md` |
| 场景 | `场景设计_名称_vNNN.md` |
| 分镜 | `分镜_场次_vNNN.md` |
| 生成合同 | `生成请求_对象_vNNN.md` |
| 视频生产 | `视频生产计划_vNNN.md` |
| 结果评审 | `生成评审_对象_vNNN.md` |

文件必须包含完整、可独立阅读的成果，不能只保存聊天摘要或修改清单。每次修订创建新版本，不静默覆盖旧版。

## 8. 第一次保存与持续保存授权

第一次需要保存时，只需告诉 Agent 项目文件夹。目录明确且保存授权有效后，Agent 会自动创建缺失的 `PROJECT_BRIEF.md`、`AUTHORIZATIONS.md`、`PROJECT_INDEX.md`、`SESSION_HANDOFF.md` 和 `DECISIONS.md`，并填入当前已知的最小信息；你不需要复制模板或填写专业字段。已有文件不会被空模板覆盖。

### 一次设置阶段保存授权

项目开始时可以说：

> 我同意：本项目今后每个阶段在我明确确认该阶段后，自动保存一个新的本地 Markdown 完整版本，并更新项目索引与会话交接；不得覆盖旧版。此同意不包含草稿保存、覆盖、删除、上传、付费、发布或研究使用。

该授权只是减少每阶段重复询问“是否保存”。每一阶段仍必须由你明确确认内容完成。

一次完整保存必须包括：

1. 创建新的阶段主文件；
2. 回读核对主文件；
3. 更新并回读 `PROJECT_INDEX.md`；
4. 更新并回读 `SESSION_HANDOFF.md`。

任一步失败，Agent 必须说“未完成”或“部分完成”并指出失败位置，不能声称保存成功。

## 9. 下次如何继续

新会话可说：

> 请先读取 AUTHORIZATIONS.md、PROJECT_INDEX.md 和 SESSION_HANDOFF.md，再读取当前阶段采用的完整文件。用普通语言告诉我已经确认到哪里，然后一次推进一个小目标。

Agent 只应把索引、交接和实际文件一致的 confirmed 内容当作事实。文件缺失或版本冲突时，应标记需要复核，不能靠聊天记忆补成定稿。

## 10. 从分镜进入 Seedance / 即梦

如果你的目标只是完成作品，可以直接要求 Agent 按以下三个成果推进：

```text
讨论到满意的剧本
→ 每个镜头都有剧本依据的分镜
→ 按镜头可直接复制的 Seedance / 即梦视频提示词
```

你不需要学习后台使用的类型理论、结构理论或景别分类。可以直接说“太普通”“不够电影感”“人物不对”“这一段太慢”“镜头太碎”或“只改第三镜”；Agent 应提供少量有明确差异的方案并保护未受影响内容。

正式生产顺序是：

```text
分镜镜头
→ production_group / Clip / DO
→ generation_request（一次平台请求）
→ 真实返回结果
→ 十维评审
→ edit_unit（剪辑实际采用段）
→ 人工裁决
```

Agent 应主动判断复杂动作是否需要拆成多次生成，并在写提示词前用普通语言解释理由。DO 或提示词写完只代表计划或请求稿完成，不代表已上传、已生成或已通过。

## 11. 平台能力和证据

时长、素材数量、声音、首尾帧、编辑能力会随模型和产品入口变化。Agent 应记录来源、核验日期、模型、入口和生成模式，不把历史经验写成永久规则。

图片不能证明运动或声音；无法观察视频时，Agent 只能列可评与不可评项，不能伪造时间码或通过结论。身份漂移是需要排查的症状，不应自动归因于角色设计错误。

## 12. 保存不等于研究同意

本地保存作品与以下行为完全分开：上传、生成、付费、发布、评测、训练、研究、公开展示和二次使用。研究默认关闭，必须另行说明用途、范围、保存期、共享对象和撤回方式，并得到明确同意。

## 13. 文件或工具不可用时

- 文件不可读：Agent 应说明哪一项不可读，并只索取继续当前目标所需的最小摘要。
- Skill 不可加载：Agent 应说明缺失专业阶段和仍能完成的部分。
- 无生成工具：仍可交付完整可复制请求、素材职责和回传清单，但不能伪造任务 ID 或结果。
- 无媒体观察能力：把不可判项标为 `unconfirmable`，不冒充看过或听过。

详细协议见 `references/novice-guidance-protocol.md` 与 `references/common-contract.md`。
