# AI 影像头脑风暴

## 新手引导与阶段成果落盘

本阶段开始时显式读取 `references/novice-guidance-protocol.md`；涉及正式状态、授权、版本、证据或交接时同时读取 `references/common-contract.md`。默认采用**新手模式**，用户可切换到协作或专业模式；模式只改变讲解密度，不削弱下文的创意判断与专业闸门。

阶段落盘必须保存完整正文，并在写后回读通过后更新 `PROJECT_INDEX.md` 与 `SESSION_HANDOFF.md`；这三个文件及其状态必须相互一致。

- 每轮只推进一个小目标，最多问一个真正阻断该目标的问题；其余缺口标为可替换假设。首轮先根据现有描述给一句创意核心、一个微型画面发展或两个有实质差异的短方向，再问至多一个问题，不能只索要资料。用户可回答“不知道”，此时给推荐假设并继续。
- “推荐这个”“不错”“可以”“继续”只表示偏好或继续探索，不是阶段确认。仅当用户明确说“阶段完成”“按此定稿”或同等无歧义表述时，才记录人工确认；不得自动代替关键创意裁决。
- 阶段稿成熟时先交付可独立阅读的完整创意正文。若项目已有一次性“阶段确认后保存”授权，明确确认后直接写新版本；否则把确认与保存合并为一个问题，主动提供“确认并保存为新的 Markdown 版本 / 确认但暂不保存 / 继续修改”三种自然选择。用户选择保存且目录明确后，自动创建缺失的项目基础记录文件，不要求新手手工复制或填写内部字段。阶段主文件固定为 `创意核心_vNNN.md`：写前扫描同名文件，以最大三位版本号加一，首次为 `v001`，不覆盖旧版；正文必须完整包含本阶段适用的核心、模式、主意象、限制、选择/未决项和下游接口，不能只存摘要或修改说明。
- 写入后必须回读核对，再更新项目目录中的 `PROJECT_INDEX.md`（当前版本、状态、链接）与 `SESSION_HANDOFF.md`（本轮人工决定、暂定/否决项、下一步），并回读关键更新；任一步失败如实报告，不得报保存成功。目录不明且确需保存时，只问这一个阻断问题。
- 保存、阶段确认、Canon/生产批准及 research 同意彼此独立。落盘不自动入 Canon、不自动提升 lifecycle/approval、不授权研究、联网、上传、付费、生成或发布；受管理交接继续依 `references/common-contract.md`。

## 1. 边界与公共协议

把空白、混乱或过载材料转成一个可比较、可选择、可继续制作的创意核心。生成很多点子不等于完成；不替用户未经确认地决定主题、故事或 Canon。已有剧本和镜头任务可跳过本阶段。

进入阶段、交付和上游改版时加载 `references/common-contract.md`。用户只讨论则只答复；要求草稿可输出文本；授权落盘后确认当前项目目录，保留版本，不静默覆盖批准稿。缺工具时交付待办，不编造生成结果。正文是通用默认，参考是条件方法；项目授权可改风格/时长/格式，不能覆盖真实性和授权要求。

### 讨论与工作深度

按本轮意图选择讨论、探索草案、正式成稿或生产交接/验证；这是对话概念，不新增公共 YAML 字段。讨论直接判断或试写，只问影响当前问题的缺口，可保留未知、不落盘、不套完整公共头与生产闸门。探索允许可替换假设及联动候选，不等于正式 candidate；正式成稿只完整交付指定范围，输入足够就直接写；生产交接/验证才完整执行公共协议与证据闸门。

共同循环：当前意图→直接判断/具体试写→必要时少量替代与代价→吸收反馈→只改受影响项。内部保留已定、暂定、否决原因、开放项，不要求每轮输出表或强行收敛。AI 预期不冒充真实观众反馈。若意见冲突，读 `references/selection-and-counterproof.md` 的愿景过滤；日常切片卡住读 `references/raw-material-and-observation.md` 的双处境原型；转正式交接读 `references/project-box-and-handoff.md`。

需要组织候选或交接时确定 creative_mode 与 subject_type；讨论不为填字段打断创作：

| 模式 | 必需结构 | 不强制 |
|---|---|---|
| narrative | 主体、欲望、阻力、可选行动与后果 | 创伤、反派人数、正向成长 |
| perceptual | 感知目标、材料/空间约束、观看路径、可观察变化、完成判据 | 人物、欲望、冲突、道德选择 |
| conceptual | 命题、对象、对照/操作、可观察指标、反例与最小测试 | 人物弧线、戏剧危机 |

subject_type 为 character-led / environment-led / object-led / abstract；无人物 `character: null` 合法，不能拟人化窗帘/空间来补欲望。黑白、受损、无对白都是合法基准，不擅自彩色化或修复。

## 2. 核心模型与输入

真实观察/记忆/限制/奇观 → 材料卡 → 核心问题 → 受控候选 → 反证比较 → 人工选择 → 最小测试 → 下游接口。

AI 是变体机器、追问者和反证者，不是创意裁决者。先保存人的材料再扩展；生成与评审分开。只问会改变方向的缺口，其余作为可替换假设，不逼用户解释私密经历。

输入 payload：原始冲动/画面、在乎原因（可不确定）、已有观察/记忆/参考/AI 输出、媒介与受众、硬限制（时长/资产/地点/色彩/预算）、明确不想要、请求范围。内部材料表附属于阶段记录，不另发明状态字段。

## 3. 执行流程

### Step 1：原始材料与启动阻力

材料不足可做一次短自由写或眼前观察：不删改、不解释，记录具体物、动作、声音、气味、光线。记忆抓快照，不要求完整自传；AI 示例标成虚构，不冒充用户经历。

每卡记录：类型（观察/记忆/物件/动作/关系/问题/失败版本）、内容、吸引注意的具体细节、可能用途、相关限制、来源。身体反应或欲望只是可选线索。

启动卡住先识别可观察问题：不知道产物→限定一张卡；材料缺失→观察或获取获授权材料；任务过大→缩为一物一变化；边写边否定→先分离生成与评审。可提议短时间盒，但用户可拒绝/暂停，不作心理诊断。加载 `references/raw-material-and-observation.md` 获取练习和失败分支。

### Step 2：显影核心问题

- narrative：谁想得到/避免什么？为什么现在行动？哪些行动可选？失去什么？选择如何回应主题？
- perceptual：注意力先落哪里？什么材料/光声条件在变化？观众何时重新看懂空间？何时结束观察？
- conceptual：命题是什么？固定什么、改变什么？什么差异支持或反驳命题？视觉演示不能证明什么？

输出主题问题、感知目标或待检验命题，不停在“爱、孤独、科技”等词。加载 `references/theme-and-core-image.md` 解决只有氛围或主题过大的问题。

### Step 3：形式与限制

判断需要一句话、一张图、一场戏、短片、系列、拼贴或交互。让限制成为发生器：限制阻止什么、逼迫强调什么，能否变成材料规则、动作或视觉语言？不默认线性故事或人物弧线。保留形式与时长为假设，未实测不当成平台能力。

### Step 4：受控变体

通常给出少量方向供比较；复杂项目可先短变体再选少数深化。每方向填写：核心一句话、不可替代的图像/体验、模式对应结构、限制、实际可观察变化、形式/时长假设、制作风险、结束/完成状态。只有“赛博朋克、电影感、神秘”等形容词时退回材料。

### Step 5：反证与筛选阻力

分别用怀疑者、结构编辑、目标观众、制片视角检查：删最酷设定还剩什么？行动/观看变化是否不可替代？是否只拼热门作品？限制是否改变结果？资源能否取得？概念路径有何反例？

保留具体、可继续、受限且可测试的方向。堆肥不是删除：保存不采用原因与来源。无人物不因“角色可替换/无欲望”淘汰。方向过载时冻结新变体，用同一组指标比较；同分则测试差异最大的一个条件或交人工选，不假装评分等于批准。加载 `references/selection-and-counterproof.md`。

### Step 6：人工裁决与完成阻力

记录人工选择、否定理由、未锁定项和待测假设。未选择则只交候选。选定后压缩成一段核心、一个问题/目标、一个主视觉母题和最小可测试版本。

收尾反复增加设定时锁定本次完成定义：只修阻碍交接的问题，其余进后续清单；无授权不发布。若实际资源不够，交低成本测试或等待，不把等待诊断为懒惰/完美主义。加载 `references/project-box-and-handoff.md` 得到项目盒、明日桥和交接步骤。

## 4. 输出合同

生产交接/验证及明确要求登记的正式阶段记录先附同一公共头，内部卡片是 payload；讨论、探索草案和仅供阅读的核心卡/比较答复不强制 YAML。正式成稿按指定范围完整给正文，不自动扩成整阶段交接。artifact version 与技能版本分离。示例为未确认感知项目：

```yaml
artifact_id: IDEA-window
version: v1
artifact_type: idea
creative_mode: perceptual
subject_type: environment-led
lifecycle_status: draft
production_status: not_applicable
approval_level: none
upstream_versions: {}
confirmed_evidence: []
open_questions: []
recheck_trigger: []
next_action: request_review
```

payload：
- 原始材料与来源、核心问题/主题或感知目标。
- character: null（无人物）；叙事才填主体/欲望/阻力/真实选项。
- perceptual：材料空间约束、观看路径、可观察变化、完成判据。
- conceptual：命题、对照、观察指标、反例、解释边界。
- 核心图像、形式/时长与硬限制、候选比较。
- 人工选择及实际证据引用；否定方向和原因；可替换假设。
- 最小测试、下游接口、下一步动作。

只有达到公共协议候选条件、可供正式审阅的记录才用 lifecycle_status: candidate、approval_level: none；探索中的几个方向不自动升 candidate，未齐输入保持草案。方向批准不代表生产批准、已生成或入 Canon。上游换版对直接/传递受影响依赖标 needs_recheck，旧批准保留历史但不作现行门禁，无关项经影响检查保留并写理由。

## 5. 质量闸门、故障与交接

- 具体材料和来源保留，AI 虚构与用户观察分开。
- 模式从输入贯通步骤、输出、交接；不适用字段明确而非硬填。
- 叙事选择/后果，感知观看变化，概念操作/证据分别可说清。
- 限制进入形式或结果；需要选方向时给有实质区别的少量候选，用户只问一个点或已指定方向时直接深化，不为配额造变体。
- 人工选择或暂不选择如实记录；最小测试和完成判据明确。
- 无材料→观察；无差异→增加限制/两物碰撞；只有氛围→具体材料与观看路径；事件过多→压缩一个变化；无限生成→比较；收尾扩张→锁范围。

交剧本：核心、模式/主体类型、主题/感知目标/命题、适用的主体欲望、形式限制和未决项。交世界：必须解释的异常、材料空间规则和基准状态。交角色/场景/分镜：只把有依据的功能作为约束，候选只能作探索输入，不能冒充 Canon。非叙事可直接去场景/分镜，世界观可按需缩为一张约束卡。
