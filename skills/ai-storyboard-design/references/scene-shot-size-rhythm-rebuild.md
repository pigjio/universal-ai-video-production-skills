# Scene 级景别与节奏重构

> 适用性：本参考提供条件性导演方法与演示案例，不是所有项目的固定镜序。无人物时人物心理/肢体条目不适用；非叙事用观看/感知任务。示例中的物件、数字、子镜编号只示范机制，不自动成为项目约束；选择省略、长镜头、反应或切镜应由当前任务与可读性验证决定。

## 适用信号

当逐镜稿满足镜号、时长、项目约定字段、道具连续性，却仍被读成“景别变化少、节奏平、像事件清单”时使用。也适用于稿件虽然频繁更换 LS / MS / CU，但每次切换缺乏叙事功能，形成机械换档的情况。

## 核心判断

**景别标签齐全，不等于形成景别句法。**

有效的 Scene 应以功能段落组织景别，例如：

```text
建立空间 → 锁定原因或证据 → 读取人物反应 → 扩展动作结果
宽 → 近 → 人物近景 → 宽
```

景别变化服务 Story Beat、观众问题和视觉强度变化，而不是为了增加种类逐镜轮换。

## 重构顺序

### 1. 先审查，不直接改镜头

对比三类输入：

1. 当前唯一剧情 Canon：决定本场必须发生什么。
2. 已成功的旧版或相邻 Scene：只提取有效的景别、静动、重音和呼吸语法。
3. 当前稿：统计景别序列、时长分布、运镜比例、Reaction 与 Hold。

审查时回答：

- 哪些关键剧情信息被复合动作吞掉？
- 哪些镜头获得了错误的同等时值？
- 是否连续使用相同强度的景别收尾？
- 近景是否用于证据、反应和选择，宽景是否用于关系与结果？
- 是真的缺少景别变化，还是虽有变化却没有段落句法？

### 2. 在文件开头先写元素分级

逐镜正文前固定写三类内容：

#### 必须独立被看见

首次揭示、剧情载体证据、人物 Reaction、主动选择、关键接触、不可逆结果、主题余波。每项原则上拥有独立注意力。

#### 必须持续成立但不抢焦点

左右手、持有者、支撑面、道具方向、固定 Hero Prop、空间锚点、屏幕方向和跨场携带路径。它们作为约束层嵌入构图。

#### 可合并或压缩

重复接近、逐段拓扑、机械复位、第二次证明、无新信息的摆动和消散。压缩后把时间还给 Reaction、选择 Hold 和结果读取。

### 3. 建立 Story Beat 控制表

每个 Beat 至少写：

| Beat | 时间 | 角色目标 / 阻力 | 信息与情绪变化 | 观众问题 | 下一 Beat 钩子 |
|---|---:|---|---|---|---|

先形成 Scene 的情绪曲线，再决定镜头数。禁止先拍脑袋设定 16 镜或 20 镜，再把事件填满。

### 4. 为每个 Beat 写景别功能组

示例：

```text
闯入：LS → CU → MLS
空间关系 → 触发原因 → 穿越结果

误认：MS → CU → MCU → MS
双方关系 → 证据 → 判断反应 → 防御结果

失控：ECU → MCU → LS
主动接触 → 突发受力 → 全身空间结果

余波：LS → CU
行动离开 → 主题载体回落
```

规则：

- 每次切换都要能说出信息功能。
- 同一 Beat 可以形成“宽—近—反应—宽”的波浪。
- 景别数量不是质量指标；段落对比与功能递进才是。
- 固定与运镜按信息、关系、情绪、视差和节奏收益比较，不限定运镜只给主要位移。接触/Reaction 中缓推可改变主观距离，缓退可揭示环境关系；代价是分散表演或泄密。若运动无收益或损害读取则固定，探索可联动比较，诊断再隔离变量；详见 visual-structure-and-space.md。

### 5. 建立 Timing 强度等级

按项目时间基准和 Animatic 读取效果建立相对强度，不把动作类型绑定到固定秒数：

```text
短促重音：已铺垫的单一接触、突发 accent
连续动作：覆盖必要起动、路径和结果
空间读取：让观众辨识陌生关系与后果
情绪停留：让反应或期待形成可感变化
```

负载闸门：若准备、接触、结果和反应抢占同一读取窗口，先减少竞争焦点，再调整时长或切点；能清晰连续读取时不强制拆镜。

### 6. 从零重写动作骨架，再补摄影字段

可将逐镜内容分为以下栏目，也可按项目模板合并或扩展，不以栏目数量验收：

1. 镜头任务
2. 构图与动作
3. 摄影机与注意力
4. 声音 / 切点 / 尾帧

先闭合动作和情绪接力，再填景别、机位、焦点与运镜。不要在旧镜头正文上只替换 `LS/CU` 标签。

## 三镜链接力检查

对每个 `A→B→C` 检查：

- A 尾帧是否给出 B 的动作或眼迹动机？
- B 是否完成一个接触、结果或 Reaction，而非重演 A？
- C 是否扩展结果或引出新决定？
- 左右手、重心、道具、屏幕方向和声音桥是否连续？

常用链条：

```text
准备 / 眼迹 → 接触 / 证据 → Reaction / 结果
近景原因 → 人物反应 → 宽景后果
宽景关系 → 特写重音 → 中近景意义
```

## 场间接口保护

重构 Scene 尾部前，读取下一 Scene 第一镜。输出状态必须明确：

- 人物位置、朝向、步幅和是否仍在回望
- 左右手与关键道具
- 引路者或对手的相对位置
- 跨切的脚步、回声、风声或音乐
- 若中间插入主题性空间切回，下一 Scene 应从此前动作势能恢复，而不是把人物状态重置

## 确定性验收

至少验证：

- 稳定镜号唯一、顺序和映射明确；连续编号按项目约定
- Scene 总时长与起止时间码闭合
- 每镜符合声明的帧率或秒制精度
- 项目约定的必要信息齐全，无冲突或无解释空项
- 固定景别或景别变化的起止、动机和观看路径明确，不强制单一景别
- 景别序列与文件开头控制表一致
- 关键左右手、道具持有、支撑面、空间锚点均有正向证据
- 逐镜正文没有负面提示词
- 只更新实际存在且授权管理的受影响版本；简表和详细稿可异文，以稳定 ID、版本、子镜映射与状态语义对齐，不要求全文一致

## 常见失败

1. **逐镜轮换景别制造“丰富感”。** 修复：按 Beat 写功能组，不以变化次数为目标。
2. **先增加镜数，再决定哪些信息重要。** 修复：先做元素分级和观众问题。
3. **连续性证明挤掉 Reaction。** 修复：连续性降为约束层，人物变化拥有独立时间。
4. **只改标题时长。** 修复：回查每个短镜的动作负载和真实切点。
5. **结尾连续宽景拉平能量。** 修复：判断最后一镜应落在空间结果还是主题载体；必要时用宽景行动后切近景余波。
6. **重构破坏下一 Scene 起点。** 修复：把下一场首镜作为本场输出接口的硬验收项。
7. **把“参考图不复述”误解为删除剧情证据。** 修复：只写剧情所需的最小载体信息，装饰性内部细节交给参考资产。
