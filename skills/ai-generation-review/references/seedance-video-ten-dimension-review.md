# Seedance 视频十维评审协议

## 适用条件

当真实 Seedance/即梦或其他生成视频可访问，需要判断可用性、续接资格、修复责任层或回归结果时加载。平台专属能力参数需实时核验；十维观察框架本身可用于其他视频模型。

## 1. 十维矩阵

| 维度 | 主要验收问题 | 最低证据 | 常见症状 | 首要区分方向 |
|---|---|---|---|---|
| 身份 identity | 脸、年龄、体型、比例、发型、服装、配件、物种、数量稳定吗 | 连续区间+目标资产/阵容 | 换脸、复制、缺人、变龄 | 错绑、参考争权、尺度遮挡、动作/运镜负荷、随机性、源资产矛盾 |
| 空间 space | 地标、入口、路线、支撑面、尺度和空间阶段正确吗 | 分镜/场景职责+连续区间 | 换侧、跳空间、拼贴、漂移 | 合法反打、后期镜像、拓扑冲突、局部读取、镜头空间链 |
| 几何 geometry | 墙、地面、桌面、门框、器具等刚性结构稳定吗 | 连续区间+必要源图 | 液化、弯折、穿模、接触高度错 | 源图矛盾、形变边界、遮挡重建、坏首尾帧、动作负荷 |
| 动作 action | 起点、预备、启动、路径、接触、结果、Reaction 是否完整 | 完整动作区间 | 跳步、合并、重演、无接触即有结果 | 提交遗漏、镜头过载、窗口、剪辑切早、参考起态冲突 |
| 方向 direction | 世界/屏幕方向、朝向、矢量、领随、左右手、视线连续吗 | 分镜轴线+连续区间 | 翻转、换位、换手、反向运动 | 合法反打、后期翻转、镜像参考、接口缺运动相位 |
| 道具 prop | 身份、数量、形态、握点、路径、接触和状态连续吗 | 资产+上传+连续区间 | 瞬移、复制、换手、错误消失 | 参考/文字冲突、卡片附属物、旧词残留、动作负荷 |
| 摄影 camera | 景别、机位、焦点、运镜触发/路径/停稳和切点正确吗 | 分镜+原片/导出 | 无因环绕、关键动作出画、末镜重构 | 提交字段、参考构图误继承、自动镜头规划、后期裁切 |
| 信息边界 reveal | 允许出现、必须画外、禁止提前出现的角色/能力/地点/声音受控吗 | 首次揭示要求+完整画幅/音轨 | 未来信息泄露、已退出主体回流 | 上传素材边缘、主体边界、覆盖过宽、有意 J-cut |
| 声音 audio | 环境音、动作音、对白、非语言声、BGM 在正确节点吗 | 实际听音轨 | 意外 BGM、错位、归属错、提前泄露 | 提交节点、模型音频、后期混音、素材音轨、需求未冻结 |
| 尾帧 tail | 末段稳定且可作为真实或文字接口吗 | 连续观看末段+原片/EDL | 漂移、扭曲、错手、仍运动、无稳定状态 | 窗口闭合、裁切、末镜负荷、上游错误累积 |

每项记录 `applicable`、requirement、evidence、scope、item_status 和 interface_impact。不适用不是 pass。

## 2. 五条硬规则

1. 身份/空间漂移是症状，不是根因结论。
2. 静帧不能证明动作顺序、方向连续、运镜路径、声音或尾帧停稳。
3. 先查实际上传、提交快照、原片和后期，再花预算做生成试验。
4. 坏尾帧不得传播；它可以触发重生成、稍早合法切点、文字或独立重启。
5. 偶然生成出的好构图/动作只登记候选，未经人工裁决不回写 Canon 或上游正式资产。

## 3. 动作与多人专项

动作按起点→Anticipation→启动→路径→接触→结果→Reaction 检查。若后镜重复进入、拿起、转身或接触，检查接口是否未写既成结果。

多人末镜出现复制/缺失时，至少比较：上传是否重复、泛称是否导致人口重采样、前镜是否建立唯一阵容和站位、末镜是否同时重构构图与集体动作、非人类主体是否缺物种约束，以及随机失败。不能直接要求重做角色母版。

## 4. 修复裁决

### 后期修复

原始生成正确，问题由镜像、裁切、变速、替换、切点或混音引入；或短暂瑕疵可无损规避，且不改变身份、空间、道具状态和动作因果。

### 重生成

实际上传错版、素材职责冲突或提交合同缺失；生成持续违背正确可执行合同；坏尾帧会污染下游；修复不改变已批准导演观看任务。

### 退回分镜

必须改变景别、机位、轴线桥、镜头数量、Reaction/Decision 节拍、首次揭示或观看任务；镜头自身没有可执行空间链或可见终点。单次随机失败不是退回分镜的充分证据。

### 退回资产层

只有源角色/场景/道具资产在必要视角或状态上确实自相矛盾，才退相应资产层。

## 5. 尾帧传播门

```yaml
tail_handoff:
  applicable: true
  observed_interval: null
  eligible_for_reuse: false
  blocked_by: []
  recommended_source: real_tail_frame | textual_reconstruction | independent_restart | none
  next_segment_obligations: []
```

尾帧必须检查身份、空间、刚性几何、方向、道具、运动相位、光色和声音尾点。不能用“已经生成”代替合格证据。

## 6. 最小试验

```yaml
minimal_test:
  authorization: null
  symptom: null
  hypotheses_compared: []
  controlled: {model: null, mode: null, duration: null, assets: [], shot_structure: null}
  single_primary_change: null
  coupled_change_rationale: null
  protected_scope: []
  stop_conditions: []
  result: not_run
  attribution_limit: 单次改善不证明唯一根因
```

合法例：保持模型、素材、镜头和时长不变，只把“全体”改为唯一阵容；或只取消后期水平翻转。若同时换模型、素材、时长、分镜和运镜，结果即使改善也不能归因。

## 7. 完成闸门

- 十维按适用性逐项有证据和范围；
- 原片、提交和导出版本可追溯；
- 事实、症状和根因假设分开；
- 修复层级有证据，保护范围与回退版本明确；
- 尾帧续接资格单独判定；
- 真实人工决定存在或明确 pending；
- 局部通过未扩大成全片通过。
