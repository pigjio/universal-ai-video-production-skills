# 证据定位、适用性与观察边界

加载条件：开始观察、用户只给截图、证据不完整、无法访问媒体或需界定可判范围时加载。

## 取证步骤

1. 冻结受评资产 ID/版本、真实文件、要求出处和实际提交记录。缺要求时先描述，不自创合规标准；缺文件只评证据缺口。
2. 核对观察能力。文件存在/元数据可读/图像已看见/视频已观看/音轨已听取是不同事实。没有对应能力就列人工待观察清单。
3. 按 creative_mode 和 subject_type 列适用项。无角色 character:null，身份与潜台词可不适用；环境评空间/材料，物体评结构/接触，抽象评范围/形态/路径/终点。静帧不评速度或动作顺序。
4. 建证据索引：证据 ID、文件与版本、来源、观察方式、范围、位置、可见或可听事实。图片区域可用文字锚点或注明坐标基准的框；视频写时间码和原片时间基准，抽样与连续观看分开；后期时间码另列映射。
5. 将要求与证据逐项对照，写 applicable、item_status、范围和理由。解释/根因不得混进事实字段。
6. 对未覆盖区间、遮挡、模糊、无声或未检查音频单列缺口，决定补证据还是交有限结论。

## 判定条件

| 状态 | 条件 | 不能替代的事实 |
|---|---|---|
| pass | 声明范围有证据满足要求 | 局部通过不是全片通过 |
| fail | 可观察事实明确违背已冻结要求 | 用户不喜欢不自动等于合同不合格 |
| suspicious | 已有具体疑点但仍有合理替代解释 | 不强行选责任层 |
| unconfirmable | 媒体类型、质量、工具或覆盖不足 | 不是 fail，也不是默认 pass |
| applicable:false / item_status:null | 该模式/媒体确实不要求此项，附理由 | 不把缺证据伪装不适用 |

视觉证据应定位“原片某时刻中央断柱基部”，不能只写“看起来不对”。连续性至少涉及有序区间及其连接；元数据含音轨只能说明容器信息，不能证明对白、音乐或同步正确。引用用户观察时标“用户报告、代理未独立核验”，不能冒充亲见。

## 具体判断示例（虚构教学材料）

要求 SCN-court:v1：左侧孔洞、中央断柱保持同一拓扑；固定机位雾从左向右流。输入只有名为 frame-demo.png 的静帧，且观察者实际看过该帧：左侧可见孔洞，断柱在中央，雾覆盖右下地面。

- E-frame：frame-demo.png，示例版本 v1，整帧及中央断柱区域，观察方式静帧视觉；事实按上句记录。
- 空间锚点在该帧满足要求：pass，范围仅该帧；遮挡后的柱体结构 unconfirmable。
- 雾运动方向与全程拓扑稳定：unconfirmable，需原片及对应区间。
- 角色身份：applicable:false，因 environment-led / character:null。
- 声音：若有声要求则 unconfirmable；若明确无需音频，则 applicable:false。两者不能混淆。
- 根因：没有已确定的运动失败，不诊断“模型方向错误”；人工决定 pending。

若当前观察者没有视觉工具，上例的 E-frame 也不得填写为已观察，只能给待人工核验表。

## 失败出口

失效链接→请求原始资源或可访问副本；只有代理图→限定分辨率可判范围；视频打不开→记录解码问题并请求转封装/原片；用户拒绝补证据→保留拒绝来源和有限结论；生成失败→评日志与输入合同，画面项 unconfirmable。所有出口都能交付报告，但不能虚构时间码、已听内容或人工接受。
