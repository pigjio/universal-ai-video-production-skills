# 基准状态与场景派生

基准状态是项目确认、可复用的稳定空间，不天然完整、彩色或无人。若需锁拓扑可移除干扰人物；若需验证尺度与动作则使用中性占位。基准为废墟时不先造一张完好建筑再损坏。

## 输入与步骤

1. 核当前母版稳定 ID、版本及真实确认依据。缺确认只建立候选，不称母版已锁。
2. 列基准：地标邻接、支撑面、尺度、相机、画幅、材质、光色与可见主体。区分空间身份和允许变化的表现条件。
3. 按任务写保持/改变/新增/删除/不得提前出现，不将“雨天”隐含成重排建筑。
4. 生成或编辑前核工具能力与授权；无工具交待办，记录 awaiting_external_generation，不编返回 ID。
5. 对照基准逐项验收，局部失败回最小层；修订累积导致拓扑漂移时从最近通过母版重派生。
6. 保存新版本与确切 upstream_versions，不覆盖原图；可回退表示文件和依赖可恢复，不代表剧情中的损坏必须可逆。

## 示例与失败分支

规范示例：SCN-hall v1 是已破损大厅；SCN-hall-rain v1 依赖 `{SCN-hall: v1}`，只新增湿痕与雨幕，地标和缺墙不变。若输出补齐缺墙，返修结构漂移，不把补墙称为好看的意外接受。图像不存在时仅能交候选差量表。

上游角色肩宽变化影响通行→场景动作包络 needs_recheck→相关分镜转身镜也 needs_recheck；保留历史批准但当前门禁失效，重审后才恢复 confirmed。只改无关配色且检查不影响本场时，可记录理由保留有效依赖。不把所有资产无差别废弃，也不放任传递依赖继续已确认。

需登记依赖的正式派生交接采用 `execution-template.md` 的公共头；不得另写 status。讨论差量不要求母版已齐或填写公共头，探索候选不是正式可交接 candidate。未经人工确认的新方向不自动成为项目事实。
