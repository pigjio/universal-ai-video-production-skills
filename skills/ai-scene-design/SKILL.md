# AI 影像场景设计｜可执行封装

## 新手逐轮引导与阶段成果落盘

任何交互先加载 `references/novice-guidance-protocol.md`；涉及状态、授权、证据、依赖或交接时同时加载 `references/common-contract.md`，二者冲突时以真实性和用户授权为最高优先。新手协议只改变对话节奏与落盘门禁，不删减本技能的拓扑、构图、光色、母版派生和生产闸门。

阶段落盘必须保存完整正文，并在写后回读通过后更新 `PROJECT_INDEX.md` 与 `SESSION_HANDOFF.md`；这三个文件及其状态必须相互一致。

- 每轮只推进 **1 个小目标**，给用户可直接选、改、否决的具体内容；最多提出 **1 个真正阻断当前小目标的问题**。“不知道/你先建议/都可以”是合法输入，立即给带假设标签的可撤销默认方案，不以问卷阻塞。首轮即交一个小产出，例如三句场景功能、文字拓扑或两个带代价的构图方向，而不是只收集信息。
- 用户可随时否决 Agent 假设；只撤回受影响项并保留原材料与已确认内容。已有材料默认局部修改，不借新手流程全量重写。跨会话先读取项目索引、阶段交接和最新版本恢复“已定/暂定/否决/未决”，不可读取时明确受阻并用用户提供的最小摘要继续。
- “不错/可以/继续/就是这个方向”等积极反馈只表示本轮方向反馈，**不等于阶段完成、保存授权或任何研究同意**。先交付当前阶段可独立阅读的完整正文。已有有效持续保存授权时，只问是否确认本阶段完成，明确确认后直接保存；没有持续授权时，用一个合并问题主动提供“确认并保存为新的 Markdown 版本 / 确认但暂不保存 / 继续修改”三种自然选择，并说明预计文件名与已知目录。只有明确确认才可标 `confirmed`；仍有阻断缺口则保持 `draft/candidate`。
- 阶段确认与写文件仍是两道门，但不得拆成两轮重复询问。目录未知时并入同一个收尾问题；用户选择保存且目录明确后，自动创建缺失的项目基础记录文件，再执行完整落盘。持续授权可跨轮沿用，用户可随时收窄或撤销，不外推到上传、付费、生成、发布、研究、评测、训练或数据留存。
- 本阶段主文件使用 `场景设计_名称_vNNN.md`（名称取已确认场景名，安全化空字符）；保存**完整正文**及必要公共头、已定/暂定/未决、依据和下游约束，不能只存摘要、聊天记录或差异说明。先扫描版本，使用下一个未占用三位号；旧版和已确认稿一律不覆盖。
- 写入后必须回读，核对文件存在、标题/版本和正文关键段完整；再更新项目索引与阶段交接中的产物路径、版本、状态、上游版本、未决项和下一动作。任一步失败都如实报告“未完成/部分完成”及失败点，不得称保存成功。文件、Skill 或媒体不可用时交付可复制的完整 Markdown 与恢复清单，不伪造写入或观察。
- 保存作品只表示用户授权把该作品写入项目目录，**绝不等于同意研究、评测、训练、公开、上传或二次使用**；这些用途必须另行取得明确、可撤销的专项同意并记录范围。

## 1. 定位与使用边界

本技能服务叙事、感知、概念型 AI 短片、短动画和教学：把“一个地点/一场戏/一个镜头”从创作意图转为**可进入、可观看、可连续、可生产**的环境方案。场景不是漂亮背景，而是主体变化、观众理解和世界规则共同发生的空间。

先按本轮意图选择：**讨论**直接答问题；**探索草案**允许暂定假设和联动候选；**正式成稿**只完整交付用户指定范围；**生产交接/验证**才加载 `references/common-contract.md` 与 `references/execution-template.md` 的完整公共头、证据和生产闸门。受管理产物上游改版也加载公共协议。讨论不要求母版、动作测试、完整 YAML、落盘或生产包；探索候选不等于正式可交接 candidate。character: null 合法；无角色作品以材料/空间约束、可观察变化和完成判据替代人物目标/阻力，不添加人物过闸门。

讨论循环：当前意图 → 直接判断或具体试写 → 必要时比较替代及代价 → 吸收反馈 → 只改受影响项。可保留未知与不收敛；内部记住已定、暂定、否决原因和开放项，不强制每轮列表。输入足以成稿时直接写，只追问会改变当前判断的缺口。

核心判断：制作空间成立不等于观众时刻知道全貌；平面、有限、暧昧空间都是可选表达。构图先比较“压力落在谁或什么上”，而非自动增加深度；光色同时决定信息何时出现。先分清缺灵感还是缺证据：探索允许联动方案，故障诊断优先单变量，批准的共享约束不静默改写。

完整生产设计可参考以下顺序；讨论和局部成稿按问题进入，不强制走完：

> 叙事功能 → 空间拓扑 → 支撑面与尺度 → 摄影机/画幅/动线 → 形式与明度 → 光色/材质/天气 → 世界观证据 → 基准图与派生状态 → 分镜/3D交接。

本技能不包含项目 Canon、个人审美偏好、某平台参数配方或平台 SOP。若需图像生成，只提供可验证的设计约束与提示词结构；平台调用服从包内相应技能或用户指定工具。

按任务条件加载：
- 构图/光影/透视诊断时读取 `references/core-methodology.md`，得到症状—修复—回归表。
- 生产交接记录时读取 `references/execution-template.md`，填公共头与适用专业字段。
- 既有母版派生、上游改版时读取 `references/state-derivation.md`，确定差量和复核传播。
- 缺灵感还是缺证据、该先验证什么时读取 `references/production-handoff.md` 的低成本入口；生产结构风险涉及动作时再做中性组合与占位测试。
- 前后台运行、构图关系语气、平面/有限/暧昧空间或联动探索时读取 `references/spatial-intent-and-exploration.md`。
- 整片配色不连贯、风格/材质/光色混淆时读取 `references/color-script.md`，制作序列颜色路线。
- 追溯方法来源或审查迁移边界时读取 `references/source-map.md`。

## 2. 触发条件与初始诊断

当用户要求设计环境概念、场景母版、局部近景、镜头空间、Light Key、材质方案、世界观地点、连续场景或场景资产清单时使用。

先判断任务类型，不要直接写长提示词：

| 类型 | 首要问题 | 首个交付 |
|---|---|---|
| 新场景 | 这个段落为何存在，主体如何行动或材料/空间如何被观看？ | 场景 brief + 拓扑草案 |
| 已有母版派生 | 哪些内容必须冻结？ | 基准图差异表 + 单变量变更 |
| 只改光色/材质 | 是否允许改结构？ | 参考职责表 + 光色/材质模块 |
| 镜头局部 | 观众必须看懂哪个动作/信息？ | 局部机位与可读性方案 |
| 连续地点 | 上一空间如何进入下一空间？ | 拓扑连续表 + 母版序列 |
| 3D/分镜交接 | 哪些约束会影响 layout/资产？ | 交接包与未决项 |

输入缺失时可做 **V0**，但必须把假设标成“待确认”，不能把猜测伪装为 Canon。若已有人工通过的母版，母版优先于一般理论；除非用户明确要求重设计。

## 3. 按范围选用的八步方法（不是每轮必走流程）

### Step 1｜提炼场景功能与信息优先级

写出三句话：
1. **功能**：建立地点/展示规则/支持行动/制造冲突/揭示信息/完成情绪转折？
2. **第一眼**：观众先看到什么？必须由一个主焦点承担。
3. **第二眼**：观众随后理解什么关系、危险、目标或世界证据？

同时列出不可丢失信息：主体位置与朝向、目标物、入口/出口、危险边界、时空状态、必须保留的负空间。没有明确功能时，先按“建立地点身份 + 支持已声明的观察/行动”提候选，不默认添加角色。

### Step 2｜建立世界观因果，而非装饰清单

用一句 premise 说明地点是什么、靠什么运转、与现实哪里不同。再回答：谁在这里生活/工作/消费？资源从哪里来？交通、能源、排水、储藏、维护如何发生？权力、信仰、气候和历史如何改变建筑、道具与材料？

每个独特造型至少绑定一个因果：资源、功能、制度、信仰、气候、冲突或生活习惯。幻想也要有现实功能锚点；“奇幻、未来、东方、废土”只是标签，不是设计证据。环境叙事用新旧、修补、磨损、临时结构、路径痕迹、阶层差异表达，并控制在次要信息层，不抢主叙事。

### Step 3｜先画空间拓扑，再谈画面风格

建立俯视或文字拓扑，至少标注：
- 边界：墙、崖、林缘、水面、天空开口、不可进入区；
- 节点：入口、出口、核心地标、交互点、冲突点、遮挡点；
- 连接：道路、台阶、桥、门、视线通道、角色行动路径；
- 支撑面：脚下站立面、座面、操作台、平台、悬挂/漂浮的受力或叙事依据；
- 层级：前/中/远景，遮挡顺序，地面—建筑—远景的相对尺度。

具象空间回答“主体受何支撑/约束、如何移动或变化、接触什么、摄影机从哪里看”；纯抽象构成按已声明形式规则检查，不硬造地面或物理机制。悬浮、断裂、无重力不是免除支撑逻辑；要说明支撑机制或明确其为异常状态。宏观地点未锁定时，先比较整体地理、行动路径、核心空间三层候选，再进入精修。

### Step 4｜确定摄影机、画幅与视觉动线

先定眼平线/相机高度、观察方向、透视类型和镜头任务，再选画幅。画幅是叙事容器，不是固定配方；常见 16:9、1.85:1、2.35:1 或竖幅都必须由信息分布决定。转换画幅时先保护角色—目标关系、方向、入口出口和主焦点，采用非对称裁切并复查动线。

构图采用：主导流向 → 转折点 → 反应/释放空间。道路、河流、光束、建筑边线既可以是视线轨道也可以是行动轨道。用前景框景与遮挡建立尺度和深度，但不要堵住关键动作。用重复建立秩序、特异制造焦点、渐变制造流动、发射强化聚焦；主次靠尺寸、剪影、明度、对比、细节密度和虚实控制。

需验证可读性时选缩略图（二值大关系）、静音单帧（当前应知方向/目标）、镜头裁切等最低成本测试。讨论可只比较方案；未观察图像不声称测试通过。有意隐藏部分关系时检查揭示时机，不要求全时清楚。

### Step 5｜形式语言与空间可读性

先定大轮廓和剪影，再定细节。硬边、尖角、直线倾向力量/人工/危险；圆角、软曲线、团块倾向有机/亲和/包覆；不要让互相冲突的形体语言无理由混在一起。检查点线面节奏、正空间实体框架、负空间呼吸与穿插；远景靠轮廓与大色块，近景 Hero 才承担高密度材质。

透视检查：眼平线是否一致？同组平行线是否指向一致消失点？圆/椭圆短轴是否符合平面法线？建筑、角色和道具是否共享尺度参照？必要时输出平面图、正交/立面参考或简化盒体 blockout，而不是用形容词掩盖结构缺失。

### Step 6｜Light Key、明度、色彩、材质与天气

生产精修且存在结构/动作风险时，按 `references/production-handoff.md` 做中性组合，验证扫掠空间、接触与机位；无角色项目只检查适用运动包络。纯光色讨论不先要求动作测试。结构失败先回布局，不用风格覆盖。序列光色及边缘、反射、水体的信息显隐按 `references/color-script.md` 处理，不将单张配色自动推广全片。

先用两到三块明度组织体积和焦点，再叠加色彩与纹理。定义主光方向、光源面积/硬软、范围与衰减、天空/环境补光、反射光、投影方向和边缘质量。阴影不是加黑：固有色受环境光与邻近反射影响；亮面、暗面、核心阴影、反射光和投影必须互相解释。硬光配清晰投影，软光配扩散边缘；多光源要检查每个投影和补光来源。

色彩只锁关系，不无条件锁死具体色值：有限色域可统一镜头组；高彩度通常集中在焦点或关键物。正常晴天、阴天、黄昏、夜景、雾雨等是条件分支，不是硬规则：依据时间、天气、叙事情绪和可读性选择。前中远景通常逐步降低对比、饱和和细节，但逆光尘雾可产生反向大气透视。

材质至少写反射/粗糙/透射特征、纹理尺度、受力与风化原因。金属依赖环境反射，玻璃同时反射/折射且边缘更显著，布料偏哑光，水面受视角、风和天空影响。污垢聚在凹处、流痕服从重力、边缘磨损来自接触；所有风化都要有原因。

### Step 7｜建立基准状态与剧情派生

先命名一个“场景基准状态”，经授权再保存：空间完整性、地标位置、支撑面、相机方向、画幅、Light Key、材质基线和风格媒介。直接采用项目确认的基准，可能是废墟、夜景、异常或角色在场；不默认要求正常、完整、彩色、无人。为隔离拓扑可暂用无人测试图，但它不反向更改项目基准。

正式派生采用差异表：保持项 / 改变项 / 新增项 / 删除项 / 不得提前出现。故障诊断优先只改一个问题簇以便归因；新方向探索可联动构图、光色、遮挡，并记录各方案整组差量，不把整组胜出归因于单一因素。授权确认后才冻结版本。稳定 ID 与 version 分离，派生记录 upstream_versions，不覆盖母版；文件可回退不等于剧情状态必须可逆。局部修正仍导致拓扑漂移，回退到最近通过版本。

### Step 8｜输出交接包并做闸门

仅在用户要求完整生产交接包时，交付场景 brief、拓扑/布局、构图与机位、Light Key、色彩/材质、环境证据、版本表、资产分级、分镜约束与 3D 未决项。局部成稿只交指定部分；探索提示词可带明确假设，不伪装生产就绪。生产提示词需已有对应执行约束；参考图逐项注明职责（结构、比例、材质、光色、笔触等），不能越权改写空间。

## 5. 参考图、生成与教学分支

- **仅做空间母版**：可移除非必要人物和小道具以隔离结构，但保留任务必需主体/尺度参照；动作验证时另放中性占位，不改项目基准。
- **局部镜头**：从已通过母版的相机方向推进；母版锁空间，局部裁切只锁区域，第一轮先保留表演负空间。
- **外部参考图**：先声明参考职责；故障诊断优先单变量吸收，探索可比较授权范围内的联动方案；色彩参考不得擅自重排已锁地标。
- **连续场景**：生产序列逐张验收入口、拓扑、方向、信息边界与光色；未通过不作下游有效依据。探索可以并排比较整条序列，不必逐张批准后才画下一张。
- **状态图**：先锁基准，再派生正常/危机/恢复、晴/雨/夜、完整/受损等状态；状态之间共享空间身份但不强行共享不适用的光色。
- **教学输出**：解释“为何这样判断”和“如何验证”，优先给表格、字段、闸门和一个最小示例，避免平台术语堆砌。

## 6. 常见失败与修复

1. 只有氛围没有拓扑：补入口、出口、节点、支撑面和行动路径。
2. 基准与差量混写：按项目确认状态拆 baseline 与 variant，不预设基准必须正常。
3. 所有颜色、材质、细节同等强：回到二值明度、主次和远近细节梯度。
4. 世界观靠装饰：为每个独特点补资源/功能/制度/行为原因。
5. 角色无法站立或交互：补支撑面、尺度参照、操作高度和受力/魔法机制。
6. 参考图重排空间：拆分参考职责，冻结不可变项，单变量返修。
7. 每个镜头重新发明地点：继承母版，记录摄影机移动与物理地标不变的区别。
8. 把 2D 概念图、3D 渲染、剧情媒介混成风格：分别记录媒介、世界规则和状态表达。
9. 用“正常完整彩色无人”做默认规范：回到项目确认基准；结构测试方式不能决定叙事状态。
