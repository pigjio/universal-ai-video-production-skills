# AI 影像角色设计｜完整可执行封装

## 新手引导与阶段成果落盘

本阶段开始时显式读取 `references/novice-guidance-protocol.md`；涉及正式状态、授权、版本、证据或交接时同时读取 `references/common-contract.md`。默认采用**新手模式**，可随时切换协作或专业模式；只调整术语和讲解密度，不删减下文的角色设计、生产判断与闸门。

阶段落盘必须保存完整正文，并在写后回读通过后更新 `PROJECT_INDEX.md` 与 `SESSION_HANDOFF.md`；这三个文件及其状态必须相互一致。

- 每轮只推进一个小目标，最多问一个真正阻断当前目标的问题；其他缺口写成可替换假设。首轮先给角色判断句、可见动作、剪影/形状提案或一项具体诊断，再问至多一个问题，不得只发角色问卷。用户可回答“不知道”，随后采用明确标注的推荐假设继续。
- “推荐这个”“不错”“可以”“继续”只更新偏好，不构成阶段确认。仅当用户明确说“阶段完成”“按此定稿”或同等无歧义表述时记录人工确认；角色内核、身份锚点、母版和生产通过等关键裁决不得自动代批。
- 阶段稿成熟时先给可独立阅读的完整角色设计正文。项目已有一次性“阶段确认后保存”授权时，明确确认后直接写新版本；否则把确认与保存合并为一个问题，主动提供“确认并保存为新的 Markdown 版本 / 确认但暂不保存 / 继续修改”三种自然选择。用户选择保存且目录明确后，自动创建缺失的项目基础记录文件，不要求新手手工复制或填写内部字段。阶段主文件固定为 `角色设计_名称_vNNN.md`，名称取用户确认的安全文件名；未知时可用明确暂名而不得阻塞早期创作。写前扫描该名称的同名文件，以最大三位版本号加一，首次 `v001`，绝不覆盖；保存约定范围内完整的角色判断、视觉/动作系统、已定/暂定/禁变项、风险与下游接口，不以摘要或修改清单代替正文。
- 写后回读核对，再更新 `PROJECT_INDEX.md` 的当前版本/状态/链接和 `SESSION_HANDOFF.md` 的人工决定、母版/未决项、下一步，并回读关键更新。任一步失败报告实际完成范围，不得声称保存成功；项目目录未知时只问该阻断问题。
- 保存不等于阶段确认、母版/Canon、生产批准或 research 同意，也不授权联网、采集、上传、付费、生成或发布；正式资产登记和交接继续执行 `references/common-contract.md`。

## 1. 目标与边界

讨论直接答本轮问题；探索可保留未知和可替换假设，不要求完整公共头、落盘或生产闸门。进入正式资产记录、生产交接/验证或处理已登记资产的上游改版时加载 `references/common-contract.md`，遵守授权写入、真实证据与依赖复核规则；独立登记产物使用 `references/state-version-and-templates.md` 的完整公共头，局部字段是 payload。

支持 narrative / perceptual / conceptual。无角色作品允许 `character: null` 并跳过造型流程；有角色但无人物冲突时，用“感知功能—身体机制—可观察动作—完成判据”替代 want/fear/flaw/弧线，相关闸门仅检查适用项。以下数量与姿态类型为完整叙事角色的探索建议，不是所有项目的最低硬配额。

把文字角色转成一个**可读、可动、可复现、可建模、可绑定、可表演、可交接**的视觉演员系统，而非只产出一张好看的概念图。

```text
角色资产 = 叙事或感知功能 + 适用的内在动机 + 核心动词
         + 形状/剪影 + 体块/比例 + 头部/表情 + 动作身份
         + 服装/道具 + 色彩/材质 + 生产约束
         + 权威母版 + 派生关系 + 版本状态
```

本技能负责角色策略、概念探索、设定规格、参考职责、母版与派生管理、生产验收和交接。它不替代：

- `ai-screenplay-development`：故事结构、人物弧线与场次写作；
- `ai-worldbuilding`：时代、文化、技术、物质与社会规则；
- `ai-scene-design`：空间拓扑、环境母版与机位；
- `ai-storyboard-design`：镜头调度、构图与连续性；
- 最终拓扑、UV、shader、绑定控制器、动画曲线或视频生成执行。

快速方案或局部讨论只交本轮需要的判断、具体提案和关键代价，不强制最小成功集。正式成稿只完成用户指定范围；明确要求完整角色包才执行适用的全部阶段，生产验证另以真实证据判定。

## 2. 运行原则

1. **功能先于造型**：叙事、感知或概念目标中的抽象形容词必须落为可观察视觉证据。
2. **大形先于细节**：先剪影、动态线、负形、体块，再服装纹理与渲染。
3. **角色是动词**：设计默认站姿、压力反应、步态与核心动作，不只设计名词身份。
4. **探索与锁定分离**：候选是候选，母版是母版；人工未裁决前不可混合成“最终版”。
5. **参考各司其职**：一张参考只承担明确职责，不允许用配色图改比例、用姿态图改脸。
6. **风格探索与锁定派生分开**：新风格探索可改比例、体块和图形骨架；已锁母版派生保护约定锚点。超界变更另开候选并请求裁决，不静默覆盖母版。
7. **生产前必须量化**：概念阶段可用范围；正式生产用 turnaround、lineup 或建模资料须锁唯一标尺，讨论和比例探索不提前强锁。
8. **最小回退**：哪里失败退回哪里，不用材质遮剪影问题，不用 prompt 加长遮结构问题。

## 3. 启动模式与停止条件

先判断 interaction_mode（仅为对话概念，不增改公共 YAML 字段）：**讨论**直接判断或试写；**探索草案**比较可替换候选，不假装批准；**正式成稿**完整交用户指定范围；**生产交接/验证**才适用证据闸门。探索候选不是正式可交接的 candidate 记录，输入不足保持草案。共同循环：当前意图 → 直接判断/具体试写 → 必要时少量替代与代价 → 吸收反馈 → 只改受影响项；允许不收敛。内部保留已定、暂定、否决原因和开放项，不每轮强制列表。再选择任务分支：

| 模式 | 典型请求 | 默认交付 | 何时停止 |
|---|---|---|---|
| 快速方向 | “给我三个角色方向” | 按要求给有区别的方向及代价，不强制核心卡/评分表 | 本轮问题已回应，可不选定 |
| 从零设计 | 从剧本建立角色 | 草案或指定范围成稿；完整包才走完整主流程 | 约定范围完成，不冒称生产通过 |
| 局部深化 | 表情、姿态、服装、三视图 | 可用暂定基线探索；正式母版派生才须锁定来源 | 局部需求已回应；验证任务才检查专项闸门 |
| 诊断返修 | 跑脸、比例漂移、不可动 | 竞争根因 + 最小修复；缺图则标假设 | 讨论给出判断；实际返修再做回归测试 |
| 既有资产整理 | 多张已通过角色图 | 权威关系 + 固定卡/档案卡 | 无冲突、无裁切、职责明确 |
| 群像/非人分支 | cast、动物、怪物 | 只加载当前问题的分支；完整包才联动主流程 | 讨论问题已回应；生产验证才检查类型闸门 |

只在缺失信息会改变**故事功能、物种/身体机制、受众安全、生产目标或现有母版权威性**时追问。其他缺口用“可替换假设”推进。用户要求逐问时，每次只问一个高影响问题；建议顺序：第一感觉 → 欲望/恐惧 → 核心动词 → 弧线终点 → 主记忆点 → 主形状 → 生产目标。

## 4. 输入契约与缺口分级

完整角色包的输入参考（不是每次对话的必填表）：

```yaml
project:
  medium: short_animation | short_film | series | other
  audience: ""
  tone: ""
  visual_style: ""
  production_target: concept | ai_image | ai_video | 3d | rig | animation | storyboard
  constraints: []
story:
  logline: ""
  theme: ""
  world_rules: []
character:
  name: ""
  narrative_function: ""
  want: ""
  fear: ""
  flaw_or_contradiction: ""
  relationships: []
  key_scenes: []
  core_verbs: []
  species_or_body_mechanism: ""
  required_props: []
  forbidden_directions: []
existing_assets:
  files: []
  current_master: ""
  latest_human_ruling: ""
```

缺口分级：

- **P0 阻断当前定稿/交接**：缺口确实影响所请求范围的功能、媒介、母版权威或文化语境时，暂停该范围的正式结论；仍可直接讨论不受影响部分、给暂定方案。不得因媒介未定阻断一次笑容讨论，也不凭空填文化事实。
- **P1 可假设**：受众、风格、部分关系或动作未定。列假设并继续到方向稿，不进入生产锁定。
- **P2 后补**：文件命名、次要表情、纹理微差。不中断核心设计。

如上游已更新，先做 delta 同步：记录新版本 → 搜索旧决策/待定项 → 标出直接及传递受影响资产为 needs_recheck；历史批准保留但不充当当前有效门禁。重审后才恢复 confirmed，无关依赖须记录保留理由。详见 `references/state-version-and-templates.md`。

## 5. 完整主流程

以下为完整包的模块库，不要求讨论逐阶段执行；只加载受当前问题影响的阶段。无实际素材/观察者时写设计预估，不冒充观众反馈。讨论与草案不以阶段闸门或完整生产测试为停止前提。

### Phase 0｜建立任务账本

**输入**：用户描述、剧本/世界规则、现有素材。  
**动作**：确定模式、目标媒介、镜头尺度、交付深度、权威文件、缺口与风险。为每张现有参考登记“贡献/不得覆盖”。  
**输出**：Input Sheet、Assumption Log、Reference Responsibility Table、当前状态。  
**闸门 G0**：P0 清零；否则不得声称已可定稿。

### Phase 1｜角色内核与设计命题

写出：

```text
这是一个[故事功能]；因为[欲望/恐惧/缺陷]，
习惯通过[3–7 个核心动词]处理压力；
观众第一眼应感到[目标感受]；
因此视觉上以[主形状、比例、姿态、表情、身份物证、色彩]证明。
```

输出 Character Core Card：story role、want、need、fear、矛盾、默认社交策略、压力反应、角色弧线、3–5 个 design pillars、3 个禁止方向。把“勇敢、内向、聪明”等词改写为胸腔方向、步幅、视线、手势、节奏、磨损等证据。

**闸门 G1**：去掉服装仍有性格；换成另一角色时，其动作策略必须改变；每个视觉支柱都能追溯到故事功能。失败退回角色内核，不开始画细节。

**讨论判断**：职业相同不等于策略相同；用同一压力下的不同动作反证设计观点，而非靠装备区分。遇到“强大但胆小，不要萌化”先保留力量体块、改避险姿态与视线。加载 `references/design-foundations.md`「观点与反证」。

### Phase 2｜功能型参考研究

建立四类参考：故事/文化证据、结构/运动机制、风格/渲染语法、禁止/反俗套。每张参考填写：

```text
提取：形状/比例/动作/材质/剪裁/行为中的哪一项
应用：角色哪个模块
不提取：哪些脸、比例、IP 特征或文化符号
风险：侵权、刻板印象、结构不可信、下游复杂度
```

不要做无注释图片堆。未经核验的文化符号不能当“氛围装饰”。

**闸门 G2**：关键视觉决定均有功能依据；不存在“整张照抄”；禁止方向可被操作性检查。

### Phase 3｜五维图形骨架与方向探索

定义并逐维验收：

1. **外轮廓**：唯一主导形；副形只制造 unity/variety/contrast。
2. **动态线**：C/S/Z、前倾、后缩或断裂；说明势能方向与张力是凝聚还是释放。
3. **内切割**：头/躯干/四肢/服装大块面比例和第一视觉焦点。
4. **具象记忆点**：1–3 个，必须绑定故事或行为；可删而不损角色者只是装饰。
5. **剪影性格**：第三人只看黑影时的第一情绪。

从零探索可比较比例、姿态、形状联动的完整方向；诊断故障才优先只改 1–2 个变量以便归因。12–40 个小剪影或低成本 6 个仅是预算示例，不是配额。不得把多个候选平均融合。评分按需使用 `references/design-foundations.md`。若感觉机械，先查等大、平行、等距和切线粘连，区分有意秩序与无意僵硬，再改一个关系比较焦点；不强制不对称，加载其中「等距与机械节奏」。

**闸门 G3**：邮票大小 1–3 秒可读；黑影能读角色功能/性格；负形不粘连；与主要角色不混；五维指向同一内核。失败只退回大形。

### Phase 4｜体块、比例与可复现公式

用 3–7 个主质量块定义 skull/head、胸腔、骨盆、四肢、手脚；标 centerline、眼线、肩线、髋线、重心、支撑面、关节点与附件挂点。建立：

```yaml
construction_formula:
  standard_pose_and_total_height: ""
  head_to_body_ratio: ""
  head_chest_pelvis_masses: ""
  shoulder_hip_relation: ""
  limb_rhythm_and_hand_foot_scale: ""
  center_of_gravity: ""
  joint_and_socket_points: []
  asymmetry: []
  deformation_rules: []
  invariant_silhouette: []
```

正/侧/背/3/4 应由同一体块推导，不能分别“画得像”。生产锁定时明确单位、姿态、端点和曲线路径，清除“约、范围、到腰”等冲突描述。

**闸门 G4**：可直接搭 3D blockout；各视图体积闭合；极端姿态仍像同一角色；比例解释年龄、力量与运动方式。失败退回体块/标尺，不靠发型遮掩。

### Phase 5｜动作身份与身体表演

从关键场次提取 5–10 个 core verbs，定义 neutral、pressure、action、social、failure 五类姿态，以及默认 gait、leading body part、energy quality、节奏与道具交互。每个姿态说明动词、态度、动态线、重心、支撑/接触状态与负形；腾空等相位可无当前支撑点，改标此前发力和后续接触。

用动画思维设计表演 beat：`notice → interpret → decide → act → react`，为眼神、头颈、肩髋、手、附件和表情残留分配动作。

动作判断沿意图 → 力入口 → 峰值 → 释放 → 锚点 → 附件响应 → 前后姿态检查，不只画一根动态线。Force 是表演启发而非力学认证，详见 `references/performance-and-production.md`「完整 Force 路径」。

**闸门 G5**：遮脸仍能读出动词；静态承重检查支撑区，奔跑、跃起、跌倒等动态失衡检查起势、惯性、接触转换和落地/恢复路径，不强制瞬时重心在脚下；相似情绪场次有可见差异；道具有携带、使用、收纳及移动状态。失败退回 force map/姿态，不加夸张脸补救。

### Phase 6｜头部、表情与手部系统

先区分结构静止位、角色习惯脸与即时表情；讨论可用暂定基线，正式派生须引用已锁来源。去掉发型检查 skull、颧骨、眼窝、鼻楔、口轮、下颌、耳位和颈部连接。识别问题优先比头形、左右眼、鼻、嘴五形的距离/大小/角度及 T 形关系，标准比例是比较尺而非平均脸目标，加载 `references/design-foundations.md`「五形与 T 形」。完整表情系统按需要覆盖基础情绪、专属反应、体力状态及强度；局部提问只做所需差量。手部定义尺度、职业痕迹、手势、持握和 rig 风险。

正式生成式派生按小模块逐项批准，Face ID → 按需表情组 → 头部多角度 → 手/道具 → 全身姿态；不固定格数。复合表情先问真实情绪与社交遮掩，再给眉眼/口部分工，允许有意冲突，比较易混读法而不平均两张脸。加载 `references/performance-and-production.md`「三层表情基线」「复合与压抑表情」。

**闸门 G6**：去发型仍可识别；习惯脸偏置有意且即时情绪差量可读；检查项目相关易混读法，不凭笑容推断真伪；强表情不换脸；脸部与身体共同支持表演意图，允许社交遮掩造成局部冲突。

### Phase 7｜服装、发型、道具与身份物证

每个主要元素回答：来自哪里、谁制作、使用多久、为何保留、如何穿戴/收纳、如何影响动作与剪影。先设计肩线、腰线、衣摆、鞋帽等大结构，再加接缝、磨损和纹理。道具是“第二演员”，必须测试持握、挥动、坐下、跑动、收纳和碰撞。

**闸门 G7**：元素同时证明身份/世界规则/行为之一；不遮挡核心表演区；技术材料符合世界上限；长发、披风、裙摆、绳带、硬饰品均有模拟/绑定方案。失败删减或重构，不用装饰解释人格。

### Phase 8｜明度、色彩、材质与风格化

先灰阶分组，再定主色/辅助色/强调色；在需要的日夜、逆光、低光和群像背景中测试分离。材质说明表面、尺度、粗糙度、磨损、年龄与身份，不把随机纹理当丰富度。新风格探索允许选择性夸张比例、体块、图形骨架；已锁母版派生只改授权变量，不默认局限三级细节，也不越权改身份。比较克制、中度、强图形候选的识别、动作和制作代价；超界另开版本，加载 `references/design-foundations.md`「风格探索与锁定派生」。

**闸门 G8**：灰阶可读；视觉焦点不被纹理抢走；角色与背景有稳定分离；同一 cast 共享 visual grammar 但主次层级不同。

### Phase 9｜特殊分支与群像

按需进入：

- **动物/非人/怪物**：先真实骨架、运动、感知器官与生态，再定拟人等级；耳尾翼触角进入表情。混合生物按“主物种负责骨架与识别、次系统补功能、材质/植物负责变化规律”设计，禁止器官清单拼贴。
- **群像**：先提取系列 DNA，再用身高、主形、体块、姿态、明度、职责物证产生差异；主角专属锚点不得下放给群众。
- **关系动作**：同一刺激下比较不同策略，以视线、朝向、距离和接触组织双人无脸姿态，再回查单体能否表演；不擅改剧本关系，最终调度交分镜。加载 `references/branches-and-diagnostics.md`「群像关系动作」。
- **既有资产/固定卡**：先指定唯一造型母版、Face ID、头部转面、配色材质、服装、手/道具、姿态的职责层级；已通过素材用确定性排版，不让生成模型重新融合。
- **多状态角色**：共同身份锚点保持；每个状态单独列触发、变项、禁变项、回归状态与派生 ID。

读取 `references/branches-and-diagnostics.md` 执行专项规则：混合生物必须闭合自然规律→结构连接→运动中间态→剧情/感知功能；系列先观察母版并做共享/专属校准；生成意外先测功能断点，不能仅因偏离文字而修回。

### Phase 10｜生产验证与角色包交付

执行四层验收：

- **A 概念通过**：内核、剪影、五维、禁止方向；
- **B 结构通过**：比例标尺、体块、turnaround、极端姿态；
- **C 表演通过**：neutral、表情盲测、姿态/动词、手和道具；
- **D 生产通过**：群像/背景可读、材质、关节范围、模拟、LOD、交接完整。

方向通过不等于生产通过。只交付用户实际需要的层级，但必须明确“尚未验证项”。完整闸门、故障树与下游清单见 `references/performance-and-production.md`。

## 6. AI 生成与迭代控制

把 prompt 当“当前阶段的执行契约”，不要把整份角色包一次塞进模型。

```text
任务类型 + 暂定基线或当前唯一母版/参考优先级
+ 本轮变量（诊断优先 1–2 个；探索可联动）
+ 必须保持的结构锚点
+ 构图/视角/输出规格
+ 禁止新增与禁止覆盖
```

迭代规则：

1. 探索轮只比较方向，不锁随机细节。
2. 每轮写 hypothesis（为何改）、delta（改什么）、evidence（如何判断）。
3. 故障诊断优先一轮一层以便归因；探索允许内核、大形、体块和表演联动，但记录差异，不把联动探索伪称单变量实验。
4. 选中的意外结果只有在增强目标功能且不破坏生产时才升级为设计；依 `references/branches-and-diagnostics.md` 检查结构、动作、记忆点与双重读取，先保留候选再记录人工裁决。
5. 若跑脸/比例漂移，减少参考冲突、缩小任务、提高母版权重；不是继续堆形容词。
6. 生成正式母版派生的 turnaround、表情或姿态前，引用已通过母版 ID 和锚点；讨论/探索可用暂定头脸或体块，明确非批准资产，不伪造来源 ID。

## 7. 状态、版本与派生协议

正式登记的独立资产采用以下公共头与专业 payload；讨论和未齐输入的探索不强制套表（完整模板见下方 reference）：

```yaml
artifact_id: CHR-example
version: v1
artifact_type: character
creative_mode: narrative
subject_type: character-led
lifecycle_status: draft
production_status: not_applicable
approval_level: none
upstream_versions: {}
confirmed_evidence: []
open_questions: []
recheck_trigger: []
next_action: request_review
payload:
  parent_id: ""
  source_master_id: ""
  module: core | silhouette | construction | face | expression | pose | costume | material | turnaround | lock-card
  invariants: []
  variables: []
  forbidden_changes: []
  human_rulings: []
  change_log: []
```

- 主版本：内核、物种、主比例或身份体系改变；旧派生全部回退审核。
- 次版本：服装状态、发型系统、表情/姿态模块扩展；受影响派生重审。
- 补丁：不改语义的小修、排版或标签更正。
- 批准只用公共 approval_level；生成进度与生命周期分别记录，`final` 不作为无条件状态。
- 上游变化后做影响传播；已废弃资产保留原因，不再作为模型参考。

模板与最小记录见 `references/state-version-and-templates.md`。

## 8. 输出规格

### 完整角色概念成稿的最小成功集

仅当用户要求完整角色概念成稿时检查以下适用项；讨论、快速方向及局部正式模块按本轮范围完成，不补整包：

1. 角色判断句；
2. 叙事适用时的 want / fear / flaw_or_contradiction，否则感知/概念功能；
3. 3 个 design pillars 与禁止方向；
4. 主形、动态线、比例、剪影锚点；
5. 默认姿态、适用的压力反应、覆盖需求的核心动词；
6. 头脸锚点与表情范围；
7. 服装/道具的功能证据；
8. 明度、色彩、材质方向；
9. 不可变/可变/禁止改变；
10. 建模、绑定、动画、镜头风险与当前批准级别。

### 完整 Character Design Packet

按需包含：Brief、Core Card、Reference Function Board、五维图形表、Silhouette Sheet、Construction Formula、Scale Chart、Turnaround、Face ID、Head Sheet、Expression/Mouth/Hand Sheet、Pose/Motion Sheet、Costume/Prop/Material Key、Cast Lineup、Do/Don’t、Model/Rig/Animation/Storyboard/Scene Handoff、Risk Register、Version Manifest。

输出必须区分：**已知事实 / 可替换假设 / 设计提案 / 人工裁决 / 待验证项**。

## 9. 快速故障定位

| 症状 | 根因层 | 最小回退 |
|---|---|---|
| 好看但不像角色 | 内核 | 重写功能句、矛盾和动词 |
| 缩小像路人 | 图形骨架 | 主形、负形、记忆点 |
| 多角度变人 | 体块/头骨 | construction + Face ID |
| 动作像人偶 | 表演 | 动词、动态线、重心、支撑 |
| 表情只换嘴 | 表情系统 | neutral 与全脸联动 |
| 换装后认不出 | 身份锚点太弱 | 强化身体/头部/姿态锚点 |
| 每轮越改越乱 | 版本/参考职责 | 选唯一母版，限制本轮变量 |
| 很酷但不能做 | 生产约束 | 关节、模拟、道具三状态 |
| 群像同脸同体 | 系列变量 | 头骨/比例/主形矩阵 |
| 角色被背景吃掉 | 明度/材质 | value separation，减纹理 |

复杂症状读取 `references/branches-and-diagnostics.md`，不得直接“重做全部”。

## 11. 最终自检

讨论/探索先检查是否直接回应当前意图、保留否决原因、只改受影响项且区分假设与证据；不要为满足下列完整包/交接清单而补无关产物。以下仅检查所请求范围的适用项。

- [ ] 边界与生产目标明确，P0 已清零。
- [ ] 内核、五维、比例、表演、服装和色彩互相支持。
- [ ] 候选、母版、状态变体和派生资产未混写。
- [ ] 所有参考有明确职责和优先级。
- [ ] 通过级别有证据，未验证项被标出。
- [ ] 失败能定位到最小回退层。
- [ ] 下游无需猜测比例、锚点、动作、材质或风险。
- [ ] 文件中没有项目 Canon、个人导演风格、平台私有参数或外部绝对路径依赖。
