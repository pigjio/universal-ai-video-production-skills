# Seedance 提示词容量压缩与无损回归

## 适用条件

仅当当前 Seedance 产品入口存在已核验的字符/令牌限制，且某个独立提交块确实超限时加载。不要因为担心过长就预先删掉导演信息。

## 1. 先记录能力证据

```yaml
capacity_check:
  platform: Seedance
  model: null
  entrypoint: null
  mode: null
  limit_value: null
  counting_method: platform_counter | unicode_codepoint | token | byte | unknown
  source_url_or_ui_evidence: null
  checked_at: null
```

旧文档、另一入口或一次报错不能自动代表当前限制。计数单位未知时标待核验。

## 2. 双版本结构

- `audit-full`：完整审核基线，保留全部约束账本和逐镜信息；
- `submission-compressed`：仅用于当前平台提交，必须指向详细版的稳定 ID/版本。

压缩版不能覆盖详细版，也不能被误当上游导演母稿。

## 3. 压缩顺序

1. 只处理超限的独立代码块；其他请求保持不变。
2. 删除行政字段、重复标题、平台看不见的本地路径。
3. 合并重复的风格、环境和主体说明，但确保每个独立请求仍自包含。
4. 缩短文学化摄影解释，保留机位、触发、路径、停稳和切点。
5. 合并同义限制，优先改成正向可见结果。
6. 最后才压缩逐镜语言；不得删除身份、数量、方向、左右手、支撑/接触、道具路径、动作因果、声音节点、可见终点和真实续接接口。

## 4. 保护区

压缩前建立不可丢失清单：

```text
请求任务与完成判据
主体白名单/画外/禁止提前出现
实际上传句柄及职责
镜头 ID、顺序和时间轴
起点、触发、路径/接触、反馈、终点
世界方位/屏幕方位/左右手
刚性几何和支撑关系
道具数量、握点和状态
声音与切点
下一请求接口
当前最关键的 1—4 条风险限制
```

## 5. 压缩后回归

- 代码块闭合且只有预期请求被修改；
- 镜头数、顺序、时长和覆盖关系不变；
- 实际素材数量与句柄不变；
- 约束账本每项仍能定位到提交文本；
- 动作因果、方向、接触和终点语义等价；
- 接口与下一请求第一镜仍一致；
- 未授权镜头和已通过基线没有顺手改写；
- 字符数通过当前入口的同一计数方法验证。

只满足字符数，不等于无损压缩通过。
