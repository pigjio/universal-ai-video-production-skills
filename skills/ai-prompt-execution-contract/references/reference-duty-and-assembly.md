# 参考职责、读取范围与提交组装

## 目的与步骤

1. 建立素材清单：稳定 asset_id、版本、真实文件/用户附件、可访问性、视觉观察方式。文件存在不等于内容已看见，文件名不证明状态。
2. 观察后逐份记录 **参考图事实→本镜读取范围→禁止继承**。多个非冲突职责可以由一张图承担，要求职责明确，不机械强制一图只能一项。
3. 用镜头 ID 将职责绑定到当前镜；材料/光线或拓扑有冲突时先决定谁控制哪个属性。主版优先也必须基于用户确认，不擅自定权威。
4. 验证平台实际接受哪些输入。上传成功要有资源回执；planned、available、visually_verified、uploaded 是素材证据阶段，不是替代公共生命周期的顶层 status。
5. 将记录层的必要常量展开进每次提交；内部 ID/路径只供记录，若平台不能读取就必须上传文件或把必要语义写进文本。
6. 记录实际提交快照，反查文字引用与实际资源一一匹配。未上传项留在计划清单，不伪装为平台素材。

## 读取范围的决策

| 参考与本镜需求 | 读取策略 | 禁止继承的例子 |
|---|---|---|
| 单一全景，任务是呈现全局关系 | 可读全图拓扑；经授权也可继承全貌构图 | 非本轮天气、偶然路人 |
| 全景但本镜是窗边特写 | 读取窗框/墙面局部的结构材料 | 全貌构图、无关区域主体 |
| 多面板/多状态组合图 | 指定唯一面板或分别绑定到不同镜头 | 其他面板的状态、分割线、标签 |
| 单物体结构图 | 全物体结构可读，姿态按镜头需要决定 | 背景台座、摄影文字、非剧情附件 |
| 材质图 | 读取纹理、反射/透明度等可见性质 | 图中的人物脸、场景布局 |
| 用户确认参考构图就是本镜权威 | 明确机位、地标及相对位置继承 | 仅排除用户批准改变的天气/状态等 |

整图与局部都可以合法。禁止的是未声明控制属性而自动复刻所有内容。全图拓扑不等于全貌取景；全貌取景也不因“局部读取规则”被禁止。

## 具体填写判断（示意事实，非本次看图记录）

假设已视觉核验的图为破损窗框、灰墙和左侧布帘：事实记录这些可见项；本镜读完整窗框关系、左侧布帘材料，并采用用户确认的全图构图；禁止继承图中暖色夕照，改为阴天漫射灰光。若只看到缩略图无法辨材质，材质写 unknown 并请求原图，不能填‘粗麻布’。

复合图按实际文件计槽位，不把四个面板说成四个已上传文件。若平台无法按面板稳定定位，可在授权下另导出裁图、建立新 asset_id/派生版本，保留原图与裁切范围；不能假称裁图已存在。

## 抽象效果与冲突素材

若图中实体与目标雾状效果冲突，先确定是否可可靠限定为轮廓参考。无法隔离语义时移除冲突图并重写正向效果合同，不期待长串否定覆盖实体先验。移除图和更新文本是一项可能必须联合的修复，应记录耦合理由和槽位变化；不要把未上传新效果写成‘图中可见’。

## 完整提交与压缩

组装顺序：任务/范围→必要风格/状态→实际素材职责→当前图像或时序描述→完成边界→少量具体高风险限制。记录层短语‘沿用上一版’必须展开为平台可见约束，除非有已验证的上下文继承机制及来源 ID。

容量不足时先移除重复形容词、行政字段及重复全局说明，保留材质本体、方向、支撑/接触、变化顺序、未变化范围和终点。压缩后比较约束账本、镜头映射和资源数量；只检查字符数不足以证明无损。

## 失败出口与验收

- 无看图工具：只做文件核验与用户提供说明，标说明来源；等待人工视觉核验，不编可见事实。
- 缺图：保持 planned；用户授权纯文字替代才另版，明确身份/拓扑保证减弱。
- 上传失败：保留可见事实但 uploaded 证据为空，修上传而非改成‘已上传’。
- 素材冲突：列冲突属性，裁决/分工/移除其一；不能未经授权重绘母版。
- 验收：每个正向约束有文本/参数/资源承载，每个实际引用有可用资源，禁止继承只列相关风险，完整提交可独立理解。
