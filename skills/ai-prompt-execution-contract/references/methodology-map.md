# 提示词合同的方法路由与交接

## 执行顺序

1. 进入、交付、上游改版先读 common-contract.md。它约束公共头、写入权限、证据与依赖失效；不重新发明 status。
2. 读 static-vs-temporal.md 选择媒体及模式字段；局部修复仍分静态/时序，character:null 合法。
3. 有参考图或需真实提交时读 reference-duty-and-assembly.md，得到素材事实、读取范围、禁止继承与完整提交账本。
4. 有运动、效果或已报告失败时读 causality-and-diagnostics.md，得到可观察变化链及竞争假设，不能跳到无证据根因。
5. 完整交付或受阻时用 worked-examples.md 校对公共头、planned/actual 区别及 pending 人工决定。
6. 追溯源版方法时读 source-map.md。源路径只是审计来源，不是运行依赖；已通用化正文可独立使用。

## 交接检查

| 上游输入 | 本阶段转换 | 下游应取得 |
|---|---|---|
| 静态资产/构图要求 | 结构、状态、材质和取景合同 | 独立可复制静态文本与参考职责 |
| 分镜/感知变化要求 | 镜头、剪辑单元、请求映射与时序约束 | 平台中立生成合同；能力未知项明确 |
| 实际失败结果及原提交 | 症状、竞争根因、区分试验 | 受授权修复候选，不冒充已通过 |
| 上游新版 | 依赖影响检查 | needs_recheck 清单和需要重审的约束 |

完成不是填满所有字段，而是每个必需判断可追溯且下一步可执行。无工具时本阶段可以完成待外部合同，生产仍未生成。

## 具体判断示例

输入‘一段没有人物的雾与玻璃变化，只有文字设想，无工具’：选择 conceptual + abstract（若玻璃物体是主角可选 object-led）、character:null；明确雾的范围/材料/路径/终点；不要求人物弧线；无实际上传则 actual_uploaded_assets 为空；交完整文本和待查能力，clip 等待外部生成。

输入‘这张截图里动作太快’：先说明截图不足以评速度，保留用户反馈来源；请求视频/区间，不用因果诊断表直接得出窗口太短。

## 常见断点与回退

- 分支选错：回媒体与目标，不继续补空字段。
- 上游版本缺失：候选/问题记录，不编批准。
- 缺图且无法观察：等待素材或经授权另走纯文字方案。
- 根因未区分：先查日志/原片，再决定是否生成试验。
- 用户只要一处修改：保护未授权文本与素材，不借方法升级全稿。
