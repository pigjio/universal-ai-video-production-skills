# Seedance 正式生成请求合同

## 适用条件

当用户要求“写成可复制的 Seedance 提示词”“展开正式 DO”“把已确认分镜交给即梦/Seedance 执行”时加载。仅要求分组时先交生产组映射，不提前展开平台稿。

本文件描述的是**通用执行结构**。`DO` 是可选的项目显示别名；内部仍区分导演镜头 `shot`、生产组 `production_group`、平台调用 `generation_request` 和剪辑采用段 `edit_unit`。

## 1. 进入正式稿前的最小输入

- 已确认或明确标为探索候选的逐镜稿；
- 本轮覆盖镜头与不可改范围；
- 每个生产组的唯一任务、可观察完成判据和不得提前出现的信息；
- 当前实际可用素材及视觉核验结果；
- 目标平台、模型、入口和已核验能力；未知项必须保留为待核验；
- 本轮授权仅写稿、外部提交或代理提交中的哪一种。

若镜头因果、空间链或首次揭示点尚未成立，退回分镜；不得用平台提示词偷偷改导演设计。

## 2. 自包含提交块

每个 `generation_request` 使用一个独立闭合的文本代码块。外部执行者只读该块和实际上传素材即可操作，不依赖本地路径、聊天历史或未打包的项目文件。

固定交付结构如下；单镜请求仅保留一个逐镜段，多镜请求逐镜完整展开，不能用“同上”替代。所有字段在同一可复制块内；韩文可翻译标题，但保持相同结构与中文固定末行。

```text
镜头编号：S01
镜头任务：观众应看到或理解什么；可观察完成判据
目标时长：本镜导演目标时长；未经测量标为估计，不冒充平台限制
景别与机位：景别、视角、高度、朝向，必要时补焦段倾向
画面构图：画幅、视觉风格、色彩、光线、场景、主体位置、前中后景与画内/画外边界
起始状态：主体身份、外观、数量、位置、姿势、视线、左右手、持有物及承接状态；有实际上传参考时写清句柄与读取职责，无素材则文字说明
动作与表演：刺激 → 接收 → 动作选择 → 对方/环境反馈 → 变化；无人时写主体变化
时间轴：按顺序安排动作节拍和停留；秒点未验证时标估计
摄影机运动：固定或主要运动的触发、路径、速度倾向与停止位置
物理与空间约束：距离、朝向、支撑、接触、重心、遮挡及材质反应
声音：逐字对白、发声者、语言、动作音效与环境声的时机；标生成/后期方案
结束状态：稳定可见的最终姿势、位置、持有物与动作结果
切点与衔接：在哪个结果切出；下一镜起点，不重演已完成动作

镜头编号：S02
镜头任务：观众应看到或理解什么；可观察完成判据
目标时长：本镜导演目标时长；未经测量标为估计，不冒充平台限制
景别与机位：景别、视角、高度、朝向，必要时补焦段倾向
画面构图：主体位置、前中后景、关注点与画内/画外边界
起始状态：明确继承 S01 的末态，写出本镜实际位置、姿势、视线、左右手、持有物与光线，不重演已完成动作
动作与表演：刺激 → 接收 → 动作选择 → 对方/环境反馈 → 变化；无人时写主体变化
时间轴：按顺序安排动作节拍和停留；秒点未验证时标估计
摄影机运动：固定或主要运动的触发、路径、速度倾向与停止位置
物理与空间约束：距离、朝向、支撑、接触、重心、遮挡及材质反应
声音：逐字对白、发声者、语言、动作音效与环境声的时机；标生成/后期方案
结束状态：稳定可见的最终姿势、位置、持有物与动作结果
切点与衔接：在哪个结果切出；下一镜起点，不重演已完成动作

高风险限制：通常 1—4 条关键错误

```

公共 YAML、审批字段、内部绝对路径和审查备注属于记录层，不粘入平台代码块。

## 3. 逐镜五字段的作用

1. **参考图锚点**：只引用实际上传项，指出本镜读取的局部/分区及职责。
2. **镜头任务**：说明观众在本镜获得什么可见信息，不重复整组任务。
3. **构图与动作**：先建立当前起点，再写触发→路径/接触→反馈→结果；只打开当前镜主要变化。
4. **摄影机与注意力**：写初始机位、触发、运动路径、停稳或切点；固定镜头直接写固定。
5. **声音/转场/切点**：将声音绑定动作节点，说明在哪个可见结果上切出或连续承接。

上述五类是内部检查维度，不是替代完整交付结构的五行简写。交付必须保留第 2 节中的逐镜字段标题；不适用写“不适用”并说明原因，未知项标待核验。不得只在块外提供景别、起始状态、目标时长或结束衔接，亦不得为凑字段编造内容。

## 4. 从导演母稿确定性展开

1. 按镜头 ID 抽取已确认的景别、机位、动作、表演、声音和时长，不擅改内容。
2. 按生产组确定唯一任务和完成判据；若两个不可替代结果争夺同组，拆组或经人工明确主从。
3. 核验素材：文件存在、已视觉确认、实际上传是三个不同事实。
4. 每个组装成独立请求块；持续环境/材质状态必须在每个独立块中自包含，除非平台上下文继承有真实证据。
5. 第一镜自然建立起点，后镜继承结果；只在真实跨请求依赖时单列续接接口。
6. 导演目标时长与平台请求窗口分开；余量只用于 handles 或既有动作闭合，不增加新剧情。

## 5. 素材与纯文字对象

每个上传素材行同时回答：

```text
实际句柄是什么
画面中确实可见什么
本请求/本镜读取哪里
它锁定哪个属性
哪些无关内容不得继承
```

复合图按独立上传文件计资源数，内部面板只作为读取分区。全景可以锁拓扑；它不自动授权复刻全貌构图。用户明确指定某图为权威构图时，才继承其机位和地标关系。

未上传但必须生成的对象、材质变化或特效不得伪装成 `@素材`。改用正向文字合同：覆盖范围、形态/材质、形成起点、运动路径、作用方式、可见终点和必要排除项。

## 6. 动作密度与拆分

以下是工程启发式，不是 Seedance 官方语法：

- 每镜优先一个主要可见变化；
- 每生产组优先一个主要任务；
- 复杂效果按形成→启动→路径→接触→结果→Reaction/代价证明拆成可观察阶段；
- 后镜不能重新执行上一镜已经完成的抵达、拿起、转身或接触；
- 多主体段先锁每镜可见白名单、站位与动作相位，再写共同动作；
- 若必须改变镜头数量、景别、机位、首次揭示或 Reaction 节奏，退回分镜裁决。

## 7. 确定性结构校验

正式交付前检查：

- 请求块数量与 `generation_request` 记录一致，围栏闭合；
- 每个视频请求代码块最后一个非空行均为“无背景音乐”，韩文稿同样保留该原文；正文不含相冲突的背景配乐要求，对白、动作音效与环境声不因此删除；
- 镜头 ID 唯一、顺序与上游一致；
- 每镜必要字段齐全；
- 镜头时长合计与导演目标闭合，平台窗口另记；
- 每个 `@句柄` 都在实际上传清单，计划素材未混入；
- 每组只有一个主要任务、一个可见完成判据；
- 后镜继承前镜结果，没有动作重演；
- 续接接口只在真实需要时存在，且与下一请求第一镜一致；
- 无占位路径、虚构回执、项目私有角色/编号或已废止状态残留；
- 官方能力、案例归纳和工程经验没有混写。

## 8. 边界

- 不把固定秒数、固定图槽数或某个 UI 语法写成永久事实；执行时读取当前能力证据。
- 不把一次项目生成成功外推为平台保证。
- 不要求外部用户访问本 Skill 的来源项目或作者本地知识库。
- 不把平台生成结果自动升级为 Canon；只能提出候选并等待人工裁决。
