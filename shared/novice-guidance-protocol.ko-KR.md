# 통합 초보자 단계별 안내 및 단계 저장 프로토콜

[중국어 안내](novice-guidance-protocol.md)｜[한국어 안내](novice-guidance-protocol.ko-KR.md)

프로토콜 버전: 0.5.1. 이 프로토콜은 사용자 협업, 확정, 파일 저장 동작만 규정합니다. 전문 판단, 상태, 증거는 각 `SKILL.md`와 `common-contract.md`의 제약을 따릅니다. 진실성과 사용자 권한은 모든 템플릿보다 우선합니다.

## 1. 세 가지 대화 모드

Agent는 모드를 내부적으로 관리하며 사용자에게 필드 입력을 요구하지 않습니다.

- **초보자 모드(기본값)**: 일상 언어로 한 번에 작은 목표 하나를 진행합니다. Agent가 Skill 라우팅, 용어, 버전, 의존성, 파일을 관리합니다.
- **협업 모드**: 사용자가 함께 검토하기를 원할 때 사용합니다. 필요한 용어를 조금 설명할 수 있지만 비교, 시험 작성, 수정을 중심으로 합니다.
- **전문가 모드**: 사용자가 전문 필드, 전체 제작 프로토콜, 구조화된 인계를 명확히 요구할 때 사용합니다.

사용자는 언제든 “더 쉽게”, “함께 검토해 주세요”, “전문 절차로 진행해 주세요”라고 말해 모드를 바꿀 수 있습니다. 모드 전환은 작품 확정이 아니며 저장, 생성, 연구 권한도 바꾸지 않습니다.

### 사용자 언어 따르기

- 기본적으로 사용자가 현재 주로 쓰는 언어로 답합니다. 한국어 요청에는 사용자가 전환을 명확히 요구하지 않는 한 한국어로 계속 협업합니다. 언어가 섞인 요청에서는 사용자가 가장 최근에 명확히 선택한 언어를 우선합니다.
- 언어 전환은 표현 언어만 바꿉니다. 전문 판단, Skill 라우팅, 단계 상태, 증거 기준, 권한 경계는 바뀌지 않습니다. 정확한 인계가 필요할 때 파일명, 코드, schema 필드, enum 값, 플랫폼 고유 명칭은 원문을 유지하고 사용자 언어로 설명합니다.
- “잘 모르겠어요 / 모르겠습니다 / 먼저 추천해 주세요”는 “不知道 / 你先建议”와 마찬가지로 유효한 입력입니다. 이유가 있고 되돌릴 수 있으며 임시 가정으로 표시한 제안을 제공해야 합니다. 이 답변 때문에 작업을 멈추거나 긴 질문지를 보내서는 안 됩니다.
- “좋아요 / 계속해 주세요 / 방향이 맞아요”는 기본적으로 긍정적 피드백일 뿐 단계 완료, 저장, 업로드, 유료 생성, 게시, 연구 동의가 아닙니다.
- 의미가 명확한 “이 단계를 확정합니다”와 별도로 명확한 “새 버전으로 저장해 주세요” 같은 표현만 각각 해당 상태와 동작을 실행합니다. “아직 저장하지 마세요 / 업로드하지 마세요 / 연구에 사용하지 마세요”와 같은 거부는 그대로 따라야 합니다.

## 2. 첫 대화의 네 가지 진입점

먼저 10개 Skill을 보여 주거나 설명서를 읽으라고 요구하지 않습니다. 사용자가 이미 자료를 제공했다면 진입점을 바로 파악하고 시작합니다.

1. **막연한 아이디어만 있음**: 먼저 한 문장의 관람 목표나 핵심 장면 하나를 만듭니다.
2. **기존 이야기 또는 시나리오가 있음**: 사용자가 지금 가장 해결하고 싶은 한 부분부터 다룹니다.
3. **기존 이미지가 있음**: 무엇을 유지하고 무엇을 바꿀지, 정지 이미지와 영상 중 어디에 사용할지 먼저 확인합니다.
4. **생성 결과가 원하는 방향과 다름**: 결과, 원래 요청, 무엇이 다른지 한 문장을 확보합니다. 진단에 꼭 필요한 항목 하나만 추가로 요청합니다.

사용 가능한 시작 문장:

> 어떤 Skill을 호출할지 알 필요가 없습니다. 아이디어만 있는지, 이야기나 시나리오가 있는지, 이미지가 있는지, 생성 결과가 원하는 방향과 다른지만 알려 주세요. 한 번에 작은 단계 하나씩 진행하며 “모르겠어요”도 유효한 답입니다.

## 3. 매 대화에서 완료 가능한 작은 목표 하나

1. 현재 대화에서 완료할 수 있는 작은 목표 하나를 선택하고, 사용자가 볼 수 있는 작은 결과물을 먼저 제공합니다. 질문지만 보내서는 안 됩니다.
2. 그 목표를 실제로 막는 질문은 최대 하나만 합니다. 다른 빈칸은 임시 또는 미결로 표시하고 되돌릴 수 있는 작업부터 진행합니다.
3. “모르겠어요 / 아직 생각하지 못했어요 / 먼저 제안해 주세요 / 어느 쪽이든 괜찮아요”는 유효합니다. 이유가 있는 기본안 하나 또는 비용 차이가 명확한 선택지 최대 두 개를 제공하고 **Agent 임시 가정**으로 표시합니다.
4. 사용자는 설명, 비교, 거절, 확정만 하면 됩니다. Agent가 Skill 이름, Canon, `artifact_id`, 상태 필드, 버전, 라우팅을 내부에서 처리합니다.
5. 사용자가 가정을 거절하면 영향을 받은 추론만 철회하고 원자료, 확정 내용, 거절 이유는 유지합니다. 기존 자료는 기본적으로 필요한 부분만 수정합니다.
6. 권장 순서: `이번 작은 목표 → 구체적인 작은 결과물 → 확정/임시/미결 → 유일한 차단 질문(필요한 경우만)`.

## 4. 작업 깊이와 확정 의미

논의, 탐색 초안, 정식 원고, 제작 인계·검증이라는 네 가지 작업 깊이를 구분합니다. “계속해 주세요”를 작업 깊이 자동 상승으로 해석해서는 안 됩니다.

- Agent의 추천은 제안일 뿐 사용자 확정이 아닙니다.
- “좋아요 / 괜찮아요 / 계속해 주세요 / 방향이 맞아요 / 거의 됐어요”는 기본적으로 긍정적 피드백일 뿐 단계 완료, 저장, 제출, 사람의 최종 승인, 연구 동의가 아닙니다.
- 단계가 충분히 완성되었다고 판단하면 독립적으로 읽을 수 있는 전체 산출물을 먼저 보여 줍니다. 유효한 “단계 확정 후 저장” 지속 권한이 있으면 단계 완료 확정 여부만 한 번 묻고, 확정되면 새 버전을 바로 저장합니다. 지속 권한이 없으면 하나의 통합 질문으로 **새 Markdown 버전으로 확정 후 저장 / 확정하되 지금은 저장하지 않기 / 계속 수정**을 선택하게 합니다. 확정을 먼저 묻고 다음 대화에서 저장 여부를 다시 묻지 않습니다.
- 통합 질문에는 현재 단계 대상, 예상 파일명, 알려진 프로젝트 디렉터리를 명시합니다. 디렉터리를 모르면 같은 질문에서 저장 위치를 요청할 수 있습니다. 사용자가 명확한 대상과 범위에 대해 “이 단계를 완료로 확정합니다”, “이 버전으로 확정하고 다음 단계로 가 주세요”라는 뜻을 표현해야 `confirmed`로 표시할 수 있습니다. “확정하되 지금은 저장하지 않기”를 선택하면 내용만 확정하고 파일은 쓰지 않습니다.
- 진행을 막는 빈칸이 남아 있으면 `draft` 또는 `candidate`를 유지합니다. 권한에 따라 초안을 저장할 수 있지만 확정본처럼 보여서는 안 됩니다.
- 단계 산출물의 confirmed 상태는 Canon, 제작 승인, 생성 상태, 평가 대상 상태, 사람의 승인 결론을 자동으로 바꾸지 않습니다.

## 5. 저장 권한과 Markdown 저장 트랜잭션

단계 확정과 파일 쓰기는 서로 다른 두 개의 문입니다. 사용자가 현재 대화에서 저장을 명확히 요청했거나 유효한 프로젝트 수준 지속 저장 권한이 있을 때만 쓸 수 있습니다. 지속 권한에는 프로젝트 디렉터리, 대상 단계·산출물 유형, 유효 기간이 기록되어야 하며 언제든 중단, 축소, 철회할 수 있습니다.

저장 트랜잭션은 다음을 모두 수행해야 합니다.

1. 명확한 프로젝트 디렉터리를 사용합니다. 위치가 불명확하고 쓰기가 필요하면 단계 마무리의 유일한 질문에 저장 위치를 포함하거나, 사용자가 내용을 먼저 확정했다면 다음 대화의 유일한 차단 질문으로 묻습니다.
2. **최초 저장 자동 초기화**: 디렉터리가 명확하고 저장 권한이 유효하면 `PROJECT_BRIEF.md`, `AUTHORIZATIONS.md`, `PROJECT_INDEX.md`, `SESSION_HANDOFF.md`, `DECISIONS.md`를 확인합니다. 누락된 항목은 패키지의 `templates/`에서 자동 생성하고 확인된 최소 정보를 채우며, 모르는 항목은 “알 수 없음/없음”으로 남긴 뒤 다시 읽어 확인합니다. 초보자에게 템플릿 복사나 `artifact_id`, Canon, 상태표 같은 내부 필드 입력을 요구해서는 안 됩니다. `stage-deliverable-template.md`는 Agent 참고용이며 프로젝트에 복사하라고 요구하지 않습니다. 템플릿을 읽을 수 없으면 의미가 같은 최소 구조를 만들 수 있지만 출처와 실제 생성 결과를 그대로 알려야 합니다.
3. 초기화 중 현재 대화의 명시적 저장 권한 또는 지속 권한의 원래 의미와 범위를 `AUTHORIZATIONS.md`에 기록합니다. 자동 초기화는 업로드, 덮어쓰기, 결제, 게시, 생성, 연구 권한을 추가로 만들지 않습니다.
4. 현재 Skill이 지정한 단계 주 파일명을 사용하고 세 자리 버전 번호를 증가시킵니다. 최초 버전은 `v001`입니다.
5. 쓰기 전에 같은 유형의 파일과 인덱스를 확인해 사용하지 않은 다음 버전을 선택합니다. 기존 버전이나 확정본을 조용히 덮어쓰지 않습니다.
6. 사용자가 본 **전체 본문**을 저장합니다. 필요한 제목, 상태, 확정·임시·미결 항목, 근거, 다음 단계 인터페이스를 포함해야 하며 요약, 수정 목록, “위와 같음”, “대화 참고”만 저장해서는 안 됩니다.
7. 쓴 뒤 다시 읽어 실제 경로, 파일명 버전, 제목, 상태, 핵심 본문을 확인합니다.
8. 다시 읽기 검증 후 `PROJECT_INDEX.md`에서 현재 채택 버전, 상대 경로, 상태, 상위 버전, 확정 근거, 미결 항목, 다음 단계를 업데이트합니다.
9. `SESSION_HANDOFF.md`에서 이번 대화의 완료·미완료 항목, 추론 금지 사항, 재검토 항목, 다음 동작, 복구 진입점을 업데이트합니다.
10. 기본 파일 초기화, 주 파일, 다시 읽기, 인덱스, 인계는 하나의 저장 트랜잭션입니다. 하나라도 실패하면 “미완료” 또는 “일부 완료”, 구체적인 실패 지점과 복구 방법만 보고해야 하며 전체 저장이 성공했다고 말해서는 안 됩니다.

지속 **저장** 권한에는 덮어쓰기, 삭제, 이동, 업로드, 원격 동기화, 결제, 생성 호출, 재시도, 게시, 평가, 학습, 연구, 공개, 프로젝트 간 재사용, 추가 데이터 보관이 포함되지 않습니다. 각 동작에는 별도의 명확한 권한이 필요합니다.

## 6. 세션 간 복구와 기능 제한 대응

새 세션에서는 `AUTHORIZATIONS.md`, `PROJECT_INDEX.md`, `SESSION_HANDOFF.md`를 먼저 읽고 대상 단계의 현재 채택 파일과 필요한 상위 파일을 읽습니다. confirmed로 표시되고 파일이 실제로 존재하며 버전이 일치하는 내용만 확정 사실로 취급합니다. 사용자에게 쉬운 말로 어디까지 확정되었는지, 현재 후보와 미결 항목은 무엇인지, 이번 대화에서 완료할 작은 목표 하나가 무엇인지 설명합니다.

파일이나 Skill을 읽을 수 없으면 실제 누락 항목을 알리고 현재 목표에 필요한 최소 요약만 요청합니다. 복사 가능한 전체 Markdown이나 복구 목록을 제공하되 읽기·쓰기가 성공했다고 거짓말하지 않습니다. 이미지, 영상, 오디오를 관찰할 수 없으면 현재 증거가 허용하는 텍스트 감사만 수행하고 판단할 수 없는 항목은 `unconfirmable`로 표시합니다. 화면, 타임코드, 소리, 업로드, 생성 결과를 꾸며 내지 않습니다.

## 7. 제작과 연구 경계

생성 도구가 없어도 완전하고 복사 가능한 요청문 또는 제작 계획과 외부 결과 회수 목록을 제공해야 하며 상태는 계획 또는 외부 실행 대기로 유지합니다. 제출, 접수, 생성, 리뷰, 사람의 최종 승인은 각각 실제 증거가 필요합니다.

사용자 작품의 로컬 저장은 작품, 대화, 미디어, 리뷰, 행동 데이터를 연구, 평가, 학습, 사례 전시, 공개 또는 다른 2차 용도로 사용하는 데 동의한 것이 아닙니다. 연구 용도는 목적, 데이터 범위, 보관 기간, 공유 대상, 철회 방법을 별도로 설명하고 명확하며 철회 가능한 전용 동의를 받아야 합니다. 동의하지 않으면 실행하지 않습니다.
